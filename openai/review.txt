**V1 – Ack storage**  
*src/plangraph/inbox/routes.py:_ack* – the key for the audit row is only set when `alarm_id` is an `int` and not a `bool`; the function then calls `store._run(..., key, fn)`.  
*src/plangraph/inbox/routes.py:_alarms* – the SQL selects rows where **no** `audit_log` entry exists with `action='ack_alarm'`, `ok = 1` and `key = 'alarm:' || CAST(id AS TEXT)`.  
Result: a refused/failed ack (audit row with `ok = 0`) never satisfies the `NOT EXISTS` clause, so the alarm stays visible. No other code creates an `ack_alarm` audit row, preventing forgery.

**V2 – Authorization**  
*src/plangraph/inbox/routes.py:_ack* – explicitly checks `principal.role` and raises `Refused("forbidden", …)` unless it is `"router"` or `"system"`.  
*src/plangraph/inbox/routes.py:read* – the `"alarms"` verb does **not** check role, permitting any authenticated principal.  
*src/plangraph/inbox/routes.py:_ack* – validates `alarm_id` with `isinstance(aid, int) and not isinstance(aid, bool)`; any bool, string or other type raises `Refused("validation", …)`.

*src/plangraph/inbox/routes.py:_alarms* – catches any DB‑error (`_UNREADABLE`) and returns `{"alarms": [], "error": "alarms unreadable: …"}`; normal empty result (no alarms) is returned without an error field, which is the expected “no alarms” case.
