**V1 – Migration safety**  
*Evidence*: `src/plangraph/keeper/db.py:_upgrade`, `src/plangraph/keeper/db.py:open_db`, `src/plangraph/keeper/daemon.py:run`  

*Assessment*  
- `_upgrade` only adds missing columns and runs `CREATE … IF NOT EXISTS` scripts; it never issues DML, so no data loss.  
- `open_db` calls `_upgrade` **after** the exclusive lock obtained by `lock_keeper` (called in `daemon.run` before `open_db`). The lock prevents any other process from writing while migration runs, eliminating concurrent‑writer race conditions.  
- The migration is not wrapped in a single transaction, but each step is idempotent. If the daemon is killed mid‑migration, the next start re‑executes the same `IF NOT EXISTS` statements and finishes safely (the doc notes this as “half‑migration”).  
- Backup procedure uses `sqlite3.Connection.backup`, which copies the DB together with WAL state; the doc’s backup step matches the recommended safe method.  

*Conclusion*: The idempotent on‑open migration is adequate for data‑preservation, locking, and concurrency. No defect identified.
