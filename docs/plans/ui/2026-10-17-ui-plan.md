## 1. Why the live page seemed out of date

- **Today it runs the code on main.** The render of `origin/main` code with the served snapshot equals the served HTML byte for byte.
  The data refreshes every 5 min.
- **It ran old code until today.** Before LIVE-SYNC-7 (2026-10-17), the render unit ran from a pinned worktree at f3bac63f. Every UI
  change since then reached the page only through that manual live sync.
- **It will drift again.** A merge to main reaches the page only when someone runs the live-sync runbook: add a detached worktree,
  then hand-edit the render unit's drop-in. The render unit and its drop-in are not in the repo.
- **Nobody can see which code runs.** The header shows the keeper head hash (`sha10`) and the snapshot time, and no code sha.
  nginx sends no Cache-Control.
- A local checkout of `main` on the workstation is 571 commits behind `origin/main`, so a page rendered from it looks very different.

The fix is items UI-VERSION-STAMP and UI-DEPLOY-AUTO: a code stamp in the page, and a deploy that follows `origin/main` after CI is
green, with a post-deploy check that the stamp equals main.
