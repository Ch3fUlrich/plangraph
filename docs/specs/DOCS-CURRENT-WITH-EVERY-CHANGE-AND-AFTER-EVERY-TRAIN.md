## Decisions

- D1. Source file: a tracked file at head under `rust/`, `src/`, `tools/` or `deploy/` that is not a doc path (`is_doc_path`). Mapped: matches a `.docs-map` glob at head. Unmapped set `U`.
- D2. Ratchet `.docs-map-unmapped.json` at the repository root: `{"unmapped": [sorted paths]}` (JSON, so the 800-line gate skips it). Generated by `python3 tools/check_changelog_docs.py --write-ratchet [--base REV]` (default base `origin/main`). When the file is absent at the base it writes `U(base) ∩ U(head)`: only paths already unmapped before the change and still unmapped, so source files the same change adds are never grandfathered. When the file exists at the base it writes `R_base ∩ U(head)` (it may only remove entries).
- D3. Coverage problems, appended to the checker's `problems` (strict fails, `--warn-only` warns): (a) each path in `U - R_head`: `<path> is a source file without a .docs-map mapping: add one`; (b) each path in `R_head - R_base` when `R_base` exists: `<path> was added to .docs-map-unmapped.json: the ratchet only shrinks`; (c) each path in `R_head - U`: `<path> is mapped or gone: remove it from .docs-map-unmapped.json`; (d) ratchet present at merge-base and absent at head: `.docs-map-unmapped.json removed`. No ratchet at either revision: coverage is skipped (fixture repos and other projects). The summary line gains `docs-coverage <len(R_head)> unmapped`. These lines start with `docs-coverage:` so callers can tell them apart.
- D4. `plangraph docs-audit [--repo DIR] [--base SHA] [--head SHA] [--cursor PATH] [--project P] [--gate KEY] [--dry-run]`. HEAD is `--head` when given (the landed sha), else the result of a fresh `git fetch origin main` (`FETCH_HEAD`), never the local `origin/main` ref. The cursor file (default `plangraph/docs-audit/<basename of repo>.cursor` under `XDG_STATE_HOME`, falling back to the home directory's state dir) holds the last audited HEAD. BASE: `--base` when it is an ancestor of HEAD; else the cursor when it is an ancestor of HEAD; else (cold or diverged cursor, no usable base) nothing is audited, the cursor is set to HEAD and the summary says `cold start at <HEAD12>` (no guessed range). The cursor advances to HEAD only when every gap of the range was filed or confirmed present (D7); otherwise it stays, and the next run audits the same range again. Cursor writes are atomic and private.
- D5. Gaps: (1) the docs-map and `docs-coverage:` problem lines (`FAIL:` prefix) of `python3 tools/check_changelog_docs.py --base BASE --head HEAD --cwd <repo>` run strict through the shared Python launcher; changelog-fragment problems are not docs gaps. (2) Stale citations: in `docs/**/*.md`, `README.md` and `CONTRIBUTING.md` at HEAD, excluding `docs/specs/`, `docs/briefs/`, `docs/reviews/`, `docs/reports/`, `docs/proposals/`, `changelog.d/` and `CHANGELOG.md`, each backticked token that is a repository path (contains `/`, no whitespace, no `..`, no `://`) or `path::Symbol` (for `A::b` chains the last segment is the symbol). A path is stale when it exists at BASE and not at HEAD. A symbol is resolved only for `.rs` and `.py` files, by its definition line, not by any occurrence: Rust `^\s*(pub(\([^)]*\))?\s+)?((async|const|unsafe|extern "[^"]*")\s+)*(fn|struct|enum|trait|type|const|static|mod|union)\s+<S>\b` or `macro_rules!\s*<S>\b`; Python `^\s*(async\s+)?(def|class)\s+<S>\b` or a module-level `^<S>\s*(:[^=]*)?=`. A symbol is stale when such a definition exists in the file at BASE and none at HEAD (a call site or comment that still names it does not keep it alive). Symbols in other file types are not resolved. Citations already broken at BASE are not this train's gap.
- D6. Commits of a gap: `git log --format=%h BASE..HEAD -- <path>` (the cited path for a stale citation).
- D7. Filing, per gap: first `GET /v1/show?key=<project>:<id>&fmt=json` through `keeper_events::Client` (present: `already filed`; HTTP 404: absent; anything else: a filing failure); when absent, one `create_items` POST through a new `Client::post_json(path, body) -> Result<Value, Refusal { status, error, msg }>` that keeps the keeper's error code and message: id `DOCS-GAP-<first 10 hex of sha256("<kind>:<target>")>` (kind `unmapped`, `mapped-without-doc`, `stale-path`, `stale-symbol`), project `--project` (default `plangraph`), kind `lane`, priority 8 (rule 3.59: LESSONS-ENFORCE items start at p8), `under` `--gate` (default `plangraph:LESSONS-ENFORCE-A-A`), description `Why:` range, gap line, commits; `How:` add the mapping and the doc, or correct the citation; done criteria `python3 tools/check_changelog_docs.py passes on a head that fixes <target>`. A `conflict` refusal whose message says the key already exists (a race) counts as `already filed`; a refusal whose `error` or `msg` names `needs_spec` is retried once with `"needs_spec": true` (the spec-admission gate, once landed); any other refusal or transport error is a filing failure. `--dry-run` prints the items, files nothing and does not move the cursor.
- D8. Output: one line per gap `DOCS-GAP <key or -> <kind> <target> commits <shas>` and the summary `docs-audit: <BASE12>..<HEAD12> gaps <n> filed <m> present <p> failed <f> ratchet <count or ->` (or `docs-audit: cold start at <HEAD12>`); exit 0 except usage errors (2) and an unreadable repository (1). The audit never fails a landing (D9).
- D9. `tools/merge_batch.py` registers `land`, `landing-record` and `settle` through thin wrappers that call the existing command and, when it returned 0, run `plangraph docs-audit --repo <repo toplevel>` as a subprocess with a 300 s timeout, copying its output to stderr; a missing binary, timeout or nonzero exit prints `docs-audit not run: <reason>` and keeps the command's exit code. Range inputs: `land` fetches `origin main` before and after the land and passes `--base <tip before> --head <tip after>` (verified by the fetch, not the local ref); `landing-record` passes `--head <args.sha>` and, when the telemetry database holds an earlier row of the same repository, `--base <that row's landed_sha>`; `settle` passes nothing (fresh fetch for HEAD, cursor for BASE). Because the cursor carries over, a landing whose wrapper did not run is covered by the next run.
- D10. The new Rust module is mapped, so the item's own head passes D3(a) without a ratchet entry: `.docs-map` gains `rust/plangraph-cli/src/docs_audit* -> CONTRIBUTING.md` (the doc of the landing tools; this item's new `docs/contributing/` fragment stands in for it). The ratchet is generated after that mapping, so it holds only paths unmapped before this item.
