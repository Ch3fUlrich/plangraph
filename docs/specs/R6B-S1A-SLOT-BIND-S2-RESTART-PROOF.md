## Decisions

- D0. Order of work. Commit 1 ports the lane file set unchanged in behaviour onto main (the blobs and hunks above; conflicts in `main.rs` and `runs.rs` are resolved by keeping main's lines and adding the lane's). Commit 2 adds the five failing tests named in Verification. Each must fail on commit 1, which behaves as df9e7fab does. Later commits fix one finding each.
- D1 (F1). Positive death proof. Add `pub enum ProcessState { Alive, Dead, Unknown }` and the trait method `fn process_state(&self, pid: u32, start_time: u64) -> ProcessState` to `GroupLiveness`. Its default body returns `Alive` when `process_alive` is true and otherwise `Unknown`, so existing fakes stay fail-safe. `LinuxLiveness` overrides it. If `/proc/<pid>` does not exist (`NotFound`), the answer is `Dead`. If the stat file reads and parses, the answer is `Alive` when the start time is equal and `Dead` when it differs. Any other read error, or a parse failure, is `Unknown`. `JobLiveness` overrides it on Windows. `OpenProcess` failing with `ERROR_INVALID_PARAMETER` is `Dead`. A creation time that differs, or a signaled process, is `Dead`. A matching, unsignaled process is `Alive`. Anything else is `Unknown`. `release_pre_exec` and `settle_abandoned` free a row only when `process_state == Dead`. `never_started` additionally requires the run record to have status `queued` and a `slot_owner` equal to `{pid, start_time}` of the row or ticket. Its existing no-process and no-`launch_started` checks and the `StartProof == No` check stay.
- D2 (F2). `SlotBind::launched` always sets `row.group = group.map(Into::into)`. A no-scope launch therefore stores `None`, the same as its record identity, and `reclaim_after` can match it. The pre-exec test in `release_pre_exec` (bound and placeholder group) stays, so a launched no-scope row is never taken for a pre-exec row.
- D3 (F3). Release on proven end, retryable. When the watcher sees `Step::Ended` for an adopted run, it releases the row matching `(run_id, pid, start_time)` of the adopted identity with `slots::release` under `slots::with_table`, then calls `touch_wake`. If the table write fails, the run moves to a `release_pending` list that the watcher thread retries every tick until it succeeds. Startup adds a second source to `gone`: every validated bound active row whose run record is terminal (`pg_worker_core::run_finished` is `Ok(true)`) and whose record `pid`, `pid_start` and group equal the row's, where `process_state` of that pid is `Dead` (`LinuxLiveness::host()` or `JobLiveness`). `reclaim_after` then frees it as it frees other gone rows.
- D4 (F4). One ticket. `Gate::acquire` no longer writes the table before waiting. The ticket that `enqueued` persisted is the run's only pending entry, and `reserve` consumes it, or creates the bound row from the configured defaults when no ticket exists, as today. A failed `withdraw` table write puts the run id into a `stale: Mutex<HashSet<String>>` of `SlotBind`. Every later `pending`, `reserve` or `withdraw` first removes this daemon's tickets and claims for the stale ids within the same `with_table` call, then clears those ids from `stale`.
- D5 (F5). Windows serving binds. Factor `slot_bind_cfg(state: &Path, reconcile_on: bool, daemon: Option<(u32, u64)>) -> Result<Option<SlotBindCfg>, String>` in `serve.rs` with the lane's field values. Off gives `Ok(None)`. On with no identity gives `Err("slot bind: daemon start time unreadable")`. On with an identity gives the config. Linux passes `group_unix::proc_start_time`. Windows passes `group_windows::creation_time(std::process::id())`, whose visibility becomes `pub`. Both `run` functions call it before `Supervisor::new`. `reclaim_after` runs `release_pre_exec` on Windows with `JobLiveness` and a new `JobScopes` `StartProof` in `reconcile_scope_proof.rs`: `group_state(job_name(unit_name(run_id)))`, where `Gone` is `No`, `Live` or `Empty` is `Yes`, and `Unknown` is `Unknown`. The module's cfg becomes `any(target_os = "linux", windows)` in `main.rs`.

## Entry points

- E1. Daemon admission: `Supervisor::start` → `Gate::{precheck, enqueued, acquire}` → `SlotBind::{claim_run, pending, reserve, launched, withdraw}`.

- E3. Serving: `serve::run` (Unix and Windows) → `slot_bind_cfg`.
