## Scope and reuse

- R1. Add one opt-in versioned JSON projection behind existing snapshot authorization. Reject repeats, extra view flags and text format for this view; preserve existing bare snapshot. Use the existing GET committed store for configured DBs; this view returns unavailable if no committed reader is configured or auth requires legacy mutable oversight accounting. Projection marker exactly md-sync-v1, plus head/head_seq, items, aliases. Capture head, aliases and planner rows inside one transaction. Reuse bulk items hydration/deps, aliases and evidence decoding; take only decision/commit evidence kind, ref and epoch (without dropping historical decision evidence needed by the ANSWERS planner), and project items to key, project, id, title, description, note, state, source, kind, wait, choices, depends_on, epoch, review_tier, evidence_kinds, done_criteria, track, evidence. Verify fields against both planner modules. Skip fleet, reviews/incidents, activity, progress, Answer lookup and decision-text construction entirely. Import uses the existing GET client with its normal 15 s read budget and validates marker and fields. If older Keeper ignores view, that first response causes a clear mismatch and no retry; activate the Keeper side before the scheduled caller. Archive keeps its existing route and budget. No persisted graph view or reusable freshness TTL. Support repeated vetted keys in the projection using committed aliases and exact key rows, dependency edges and keyed evidence, with parameterized set-based queries in the existing StoreSupport (no full scan for one key). Use at most 32 requested keys and 4 KiB encoded request-target in targeted mode. Over that cap select the same narrow all-rows view once, before making any GET. No retry with broader scope after an HTTP error or malformed view. Both modes stay within one committed transaction.
- R2. Bind each plan to three exact source bytes and the projected head_seq. Use one DecisionsAdapter instance reading the captured decision text through a read-only from_text constructor, so parse and Closes checks use the same bytes; re-read and compare source digests immediately before each submit, keep authoritative ANSWERS file pin and server validation, and rebuild the entire plan at most once after a proven source or precondition refusal. Never submit the plan from an earlier attempt. Emit base_seq via the existing batch payload. Expose optional typed callbacks through apply_batch.main and apply_batch_atomic.send, preserving their existing defaults and transport. Before post, the callback must successfully persist the existing operation identity and the separate input watermark. After post report committed (matching complete reply), rolled_back (definite Keeper refusal), or unknown. A pre-POST failure leaves no new journal. If the client cannot classify an outcome, keep the marker. Use the existing conflict code plus the server's base_seq marker to distinguish the precondition rollback from an item-level refusal. For the router md-sync batch with base_seq, extend Store._check_base_seq to validate relevant touched targets across edit/add_evidence/legacy_state/close/create and referenced dependency endpoints under the same BEGIN IMMEDIATE and using existing _op_keys/resolution. Retain original request keys for alias-change conflicts. Prevent cross-project duplicate creation by joining candidate create IDs against items having key events after base_seq; ordinary unrelated key commits do not conflict. Keep recognized base_seq refusal as batch rollback/replan, never item drop; leave bounded existing known refusal/drop and already-DONE reconciliation for definitive server refusals only. Keep existing authority and transaction, no bypass or split, no expansion of privileged op kinds.
- R3. Scheduled mode requires --apply and --status-file. Linux advisory nonblocking flock on a private per-mode-600 sidecar keyed by canonical status path; hold from before input until final write and never unlink the lock file. Crash releases OS lease. Cooldown uses stored UTC completion plus 600 seconds, the documented 10-minute cadence; on backwards/corrupt clock state emit a fixed reason and hold for operator reconciliation, and do not replace completed timestamp on a competing/too-soon invocation. Path wakes during cooldown defer but next eligible run reads current source bytes and protected refs even if source digest is unchanged. Apply the cursor rule below. An unresolved external merge or graph dependency is pending, so unchanged files never suppress that work. Document OnUnitInactiveSec=10min with existing boot/path triggers, shared status path and optional installer verification; installed unit changes require separate authorization. Manual dry-run and archive keep their existing behavior; apply instances targeting scheduled state use same lock and unresolved journal, never a separate bypass.
- R4. Before scheduled apply POST, durably record pending window/operation fingerprint, source digest and base_seq to a separate private sidecar via same-directory atomic replace, fsync file and directory. Clear after confirmed success or a definitively pre-POST failure/atomic rollback; ambiguous network or malformed success, crash, unreadable journal or failed receipt persistence leave the next scheduled apply blocked for authoritative operation history reconciliation. Identity is the existing apply_batch reconciliation fingerprint and not a server idempotency key. No blind replay or persisted stale return. Overlap skip emits structured stderr without overwriting the active run's file.

- R6. Incremental scheduled data watermark. Under the scheduled lease, maintain durable settled decision row fingerprints with maximum D-id, verified source prefix byte count/hash and independent QUESTIONS/ANSWERS/config-input hashes. Full initial bootstrap only through the narrow all-rows view. Parse the captured decisions bytes through the existing canonical parser, detect append-only input by hash of the prior prefix, and select precisely the newly added decision rows plus durable still-pending D-ids. Fold these keys through the entire DecisionsAdapter on the frozen bytes so supersession logic sees relevant prior rows; never evaluate earlier settled unrelated keys. Revisit in-review, nonterminal, refused or await-deploy decisions as pending, even when the source is unchanged. Including pending IDs is required when a protected origin ref changes out of band. With matching input digests, no pending work and no new canonical decision row, report unchanged with zero Keeper reads. Prefix rewrite, deleted/reordered prior rows, changed Q/A/config identity, missing/corrupt cursor without unresolved submission, or an above-cap key set select one all-row narrow reconciliation, with old full plan semantics and no full snapshot. Unknown submission is a separate stop, not a cache miss. Advance the cursor only for parsed and durably reconciled decisions after known apply outcomes or proved no ops. Keep pending rows until durable terminal/invalid disposal. Never save stale plan results across retries, advance while in doubt, or bypass canonical policy. Collect and test edit/rewrite, pending then freshly available merge/live evidence, unrelated state changes, and legacy large Q/A import.
