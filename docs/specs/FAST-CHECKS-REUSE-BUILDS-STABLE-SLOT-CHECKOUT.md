## Premise at the base

- Owned fast checks resolve HEAD, create a random `check-…-fast` linked worktree, start a new CLI there, then forcibly remove the worktree before publishing the receipt. The child acquires its target after selection and replay. Every fresh checkout writes fresh copies of checked-out files. Cargo's local-source mtime checks make a warm target vulnerable to this churn. The claim about every workspace crate being dirty depends on what was selected and what Cargo actually sees. Measure the rebuild set in D1. [rust/plangraph-cli/src/fast_check_worktree.rs:26–71; rust/plangraph-cli/src/fast_checks.rs:388–412,425–457] [Cargo build cache](https://doc.rust-lang.org/cargo/reference/build-cache.html) [Cargo issue 6529](https://github.com/rust-lang/cargo/issues/6529)
- Fast checks already disable incremental compilation at line 440. Native Codex does the same and retains its editable worktree and inherited shared target across turns. Both dev profile tables set optimization and leave debug info at Cargo's default full level. The cited 16–31 GB slot spread is incident context. The tree documents 20.9–25.9 GB for a cold full-workspace debug test build. [rust/plangraph-cli/src/fast_checks.rs:425–441; rust/pg-spawnd/src/native_writer_host.rs:193–216; rust/pg-spawnd/src/native_writer_session.rs:54–63; rust/Cargo.toml:6–14; docs/operations/spawner-disk-admission.md:24–32] [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html#debug)
- Native writer exit and Python preflight invoke post-run cleanup. It uses 75% for stale variants and the hard cap for whole debug profiles. The separate pool and timer already use leases and hard-cap/pressure checks. No source proves that every run empties a slot or starts the next run cold. D-7059 records the build-host grant with free space rising from 19 to 48 GB in the router record (router/CHANGELOG.md:9). The brief's 33.3 GB deletion is reported incident data with no matching per-run byte measurement in this tree. [rust/pg-spawnd/src/native_writer_session.rs:152–165; tools/preflight.py:766–778; rust/worker-core/src/disk_runtime.rs:372–404,496–551; rust/worker-core/src/cargo_pool_trim.rs:275–345; rust/worker-core/src/disk_hygiene_plan.rs:295–328]
- sccache already has a digest-pinned explicit setup component for Linux x86-64, a shared Python resolver used by preflight, and documentation for CI, hooks and `SCCACHE_BASEDIRS`. Rust fast checks currently only inherit a wrapper if one was configured upstream. The named host's installation status is a live claim and cannot be inferred from those files. The gap here is resolving and forwarding the host policy in the Rust gate. [setup/manifest.toml:8–20; src/plangraph/spawner/host_ready.py:82–124,669–690; docs/host-tools.md:40–54; docs/TESTING.md:83–101; rust/plangraph-cli/src/fast_checks.rs:430–457]
- Ordinary slot count is disk-only today, clamped to 1–3 with a default of three on unknown disk or zero measured bytes. The measurement also sees review directories. Review slots have their own fixed aggregate multiplier and must keep it. [rust/worker-core/src/cargo_pool.rs:96–123,126–178; rust/worker-core/src/cargo_pool_trim.rs:348–373]

### Implementation

- Lease and source identity. Resolve the primary once in the initiating lane, before changing the check cwd, including existing relative-path expansion and symlinked ancestor handling. Use the existing `SlotLease` to derive `<primary>-pool/sources/<repo-id>/<slot-name>-src`, with full SHA-256 of the canonical common Git directory path bytes for `repo-id`. Slot 0 uses the primary basename, and other slots use their existing `slot-N` names. Keep sources under the excluded pool root, outside the target slot paths. Hold the exclusive target lease before checking, creating or updating its source through all Cargo and other check steps and receipt settlement. Use slot lease then Git mutation lock, releasing the Git lock before running checks. Keep the existing 30-second wait for slots. A second run cannot touch the first run's source, including when they use different linked lanes in one repository. Record the actual slot selected. Retain normal first-free ordering. A build from an intervening interactive or writer checkout sharing that target can make Cargo dirty again. The guaranteed warm path is consecutive owned invocations in the same slot with compatible inputs and no intervening external rebuild.
- Owned Git lifecycle. Check the exact resolved head before work starts. Make the source container private to the current user. Validate real, owned, canonical pool-created components, outside the lane and common Git directory, and reuse the existing mount guard for the source subtree before destructive Git steps. Reject overlap, symlink, foreign owner, nested mount and unregistered nonempty source. Under the Git mutation lock, create missing sources with `git worktree add --detach --lock --reason plangraph-fast-check-slot -- <source> <head>`. Use the exact absolute unquoted source entry and lock reason from the NUL-delimited worktree list, and check common-dir, top-level and detached identity after checkout. On a clean registered source run `git checkout --detach <head>` (skip Git checkout when already at that head). Inspect `git status --porcelain=v1 -z --untracked-files=all --ignored=matching` before and after preparing the source. If it reports dirt, use `git checkout --detach --force <head>` for tracked/index dirt and `git clean -ffdx` for untracked/ignored dirt, confined to the verified disposable slot source. Validate clean status and the exact head before executing any step. Persist the verified Git administration directory name and source identity in a sibling private sidecar. On recovery require the exact locked list entry and the recorded admin directory's `gitdir` backlink to the expected source. If creation was interrupted before the sidecar write, accept only the locked listing plus a reciprocal `.git` pointer and admin `gitdir` backlink. Validate deletion boundaries at the source and the Git administration directory. A corrupt or vanished checkout with attributable registration is recreated once under the same lease and Git lock using `git worktree remove --force --force -- <source>` followed by the normal add. Refuse if removal or proof fails. A mismatched directory, registration, or lock reason is a refusal. No global Git prune, no cleanup of the caller lane and no deletion of the target during source repair. Existing registered disposable `*-fast` entries retain normal retirement. Persistent sources are outside the ordinary slot list and registered locked, including while idle. [rust/worker-core/src/cargo_pool.rs:126–159,181–196; rust/worker-core/src/cargo_pool_trim.rs:23–38,222–245; rust/worker-core/src/disk_hygiene.rs:603–649; rust/worker-core/src/disk_hygiene_plan_discovery.rs:94–141]
- Interruption and settlement. Before source creation/update or child spawn, atomically write a private `<slot>.fast-check-in-flight.json` marker beside the target, including repository identity, canonical target, exact source and run identity.
