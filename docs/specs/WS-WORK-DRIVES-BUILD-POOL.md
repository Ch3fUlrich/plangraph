## Decisions

- D1. Keep the worktree and build selections independent. Introduce `cargo_build_target::resolve` in worker-core as the one Rust entry for selecting or validating the Cargo placement for a build run. Reuse the list and percent parsing, `select_with`, `MIN_FREE_BYTES`, `DiskSpace::meets_floor` and `disk_space`. Extract the reusable configured-list selection before appending the worktree suffix. Cargo adds its own mount validation, primary suffix, serializable placement and pin validation. The fixed target comes from `cargo_cache::shared_cache_roots`, and pool acquisition receives an explicit primary. The spawner and feeder already share the worktree selection. [rust/worker-core/src/work_disks.rs:10–46,100–128; rust/worker-core/src/disk_runtime.rs:49–83; rust/worker-core/src/cargo_cache.rs:10–18,82–112; rust/worker-core/src/cargo_pool.rs:389–405; rust/pg-spawnd/src/native_writer_commands.rs:112–133; rust/plangraph-cli/src/feeder/sources.rs:259–266]
- D2. `PLANGRAPH_BUILD_MOUNTS` is an ordered colon-delimited Linux list of UTF-8 absolute canonical mount-point paths. Preserve literal spaces. Reject empty fields, control characters, relative paths, aliases, dot components and `/` as individual unusable entries. A wholly empty value, like an unset value, selects legacy mode. Deduplicate exact repeated entries at first occurrence. For an active list take the eligible mount with the most available bytes, with ties resolved by first list position. Use `PLANGRAPH_DISK_MIN_FREE_PERCENT` as-is, default 10, valid range 1 through 99. Eligibility requires positive total, free at least 5 GiB and `free * 100 >= total * percent` in wide arithmetic. Keep the exact existing percent errors. A nonempty list with zero eligible mounts refuses. In legacy mode use `PLANGRAPH_CARGO_TARGET_DIR` when set, preserving Rust's existing tilde and relative-to-launch-cwd rules, then the existing cache-directory default. Require the resulting target to satisfy the caller's existing checkout separation and safety checks. `CARGO_TARGET_DIR` is a transport and Cargo setting. Specific explicit target consumers described below validate it against placement. [rust/worker-core/src/work_disks.rs:13–46,60–81,109–128; rust/worker-core/src/disk_runtime.rs:55–60; rust/worker-core/src/cargo_cache.rs:56–112]
- D3. For a listed mount, require a canonical directory that is an exact entry in the current Linux mount table and has a different `st_dev` from its immediate parent. Reuse the mount-table parser. A bind on the parent's device, dangling link, symlink alias, missing mount or plain directory fails. Sample the verified mount device itself. Use effective-credential write and search permission and the read-only filesystem flag to reject unwritable mounts. Inspect existing `plangraph`, primary, pool, prospective slot and lock paths without following links. Require real same-device directories at directory positions, regular files for existing lock files, effective write/search where applicable, and no intervening or nested mounts in the managed paths. A missing managed child is eligible. Record stable rejected-path reasons `invalid mount path`, `work mount unavailable`, `work mount is not a separate filesystem`, `work mount is not writable` or `unsafe build cache layout` according to the first failed check. A mount-table or metadata failure is unavailable. Use the same validator without the write requirement to inventory read-only roots, and report those roots as kept. [rust/worker-core/src/work_disks.rs:67–93; rust/worker-core/src/reap_journal.rs:238–295; rust/worker-core/src/cargo_pool_trim.rs:220–245]
- D4. Return an immutable placement with `primary`, `mount`, `device`, `inode`, `free_bytes`, `total_bytes` and `skipped`. Include `samples`, the configured paths in order with `free_bytes`, `total_bytes` and `eligible` where sampled, or with a rejection reason. Use null for mount, identity and samples in legacy mode. Each skipped row has `mount` and `reason` and, when sampled, both byte counts. Preserve list order. An unavailable or low mount is named even on success. At admission take one sample per eligible path. Keep the returned primary across steps, artifact staging, cleanup and further turns of the same run. A changed mount winner affects new runs. A resume of an older run whose record lacks placement selects once at resume admission and persists it. A record with a pin keeps it and revalidates that mount's availability, identity and floor at resume. A live process revalidates identity at managed operation boundaries without reranking or enforcing the admission floor again. On identity loss return `disk_low: pinned work mount unavailable: <mount>`. Provision managed children relative to an opened verified mount directory, using no-follow directory opens and `mkdirat`, and retain the directory handle on Linux while setting up and running a build. Recheck path identity before passing the absolute path to a child. The launcher never creates the listed mount. Forced or lazy detaches during active builds are outside rollout.
- D5. Use the `select_with` error unchanged when no entry passes, including the final close parenthesis, spaces, byte units and configuration order. The template is `disk_low: no work mount meets 5 GiB and <P>% free (<mount>: <free> of <total> bytes free; <mount>: <reason>)`. When all mounts are measurable and below threshold, every row uses the exact byte-count form. A skipped invalid entry has its reason in place of counts. Pass the string unchanged in the native `refused` record with exit code 8, in the Python admission reason, in fast-check stderr with a nonzero process status and in readiness errors. The existing native disk branch already writes the record in this shape. [rust/worker-core/src/work_disks.rs:18–45,120–127; rust/pg-spawnd/src/native_writer_commands.rs:117–129; src/plangraph/spawner/host_ready.py:518–525; rust/worker-core/src/bin/pg-host-readiness.rs:80–105]
- D6. Each mounted primary is `<mount>/plangraph/cargo-target`. Ordinary and review slots stay in its sibling `cargo-target-pool` under existing naming and lease rules. A winner change starts with the destination's existing idle cache or a cold empty cache. Create each on demand. Cross-mount copying, linking, migration and eviction at switch time are outside this design. Previously used pools remain eligible for cleanup. At the default 32 GiB cap a fully used ordinary three-slot pool can retain about 96 GiB per mount plus the existing review allowance and private artifacts. Two fully used pools can therefore retain about 192 GiB of ordinary artifacts before hygiene, with transient overshoot possible. The per-device caps and pressure cleanup run on every present root. Keep the existing path-scoped build and trim leases. Lock contention on the chosen target keeps the existing failure or bounded slot wait. [rust/worker-core/src/cargo_pool.rs:23–30,96–124,162–179,266–304,389–425; rust/worker-core/src/cargo_cache.rs:184–241; rust/plangraph-cli/src/fast_check_target.rs:112–145]
- D7. A role or mode already entitled to an isolated Cargo target stays isolated. Build-mount mode places managed private preflight output beneath the pinned primary's parent using its existing `preflight-cargo-*` allocator and cleanup. Keep its existing sccache and free-space eligibility. A configured private-parent override in build-mount mode is valid only when it resolves to that same parent. Treat an invalid override as unavailable private placement and use the pinned shared primary. In legacy mode keep operator-supplied private configuration. A configured `PLANGRAPH_CARGO_TARGET_DIR` can still name a hand launch's private target only when the build mount list is unset or empty for that invocation. Keep the target fixed for that run and avoid copying any cache. Explicit disposable review-workspace targets retain their own path, cleanup and lease contract. Global compiler cache variables keep their existing scope. [tools/preflight.py:326–406,713–723; rust/pg-spawnd/src/hand_run.rs:13–19,83–84,116–122,138–154; src/plangraph/spawner/runner.py:276–284,479–481; src/plangraph/spawner/host_ready.py:82–125]
- D8. Operator measurements on 2026-11-26. The work host's roughly 1,081 G root disk dropped from 108 G free to 12 G in 54 minutes under about 15 Cargo builds. A 688 G ext4 disk was attached that evening under /mnt. Its logon attachment can leave a dangling symlink or an empty directory after a guest restart. The search covered the Plangraph config directory, systemd user environment and environment.d, and found neither target nor worktree mount override. Observed use was 44 G in shared target, 54 G in pool slots and 115 G in hand-launched private targets. Those units set the target override to the extra disk, where the first full check took about 50 minutes. One native writer ended with `CARGO_TARGET_DIR: shared cache is being reclaimed` as checks began. The Python and Rust default paths are independently calculated at this base, and the Rust writer lease emits that exact contention error. [src/plangraph/spawner/host_ready.py:77–83; rust/worker-core/src/cargo_cache.rs:82–112,191–203]
