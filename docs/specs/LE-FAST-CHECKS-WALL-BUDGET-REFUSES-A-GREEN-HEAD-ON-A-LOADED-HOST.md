# LE-FAST-CHECKS-WALL-BUDGET-REFUSES-A-GREEN-HEAD-ON-A-LOADED-HOST

Outcome. A fast-checks run that passes every check gets its receipt on a loaded host; the 300 second budget is measured and reported, and does not alone refuse the head.

## Decisions

- D1. Choose (a). Keep 300 seconds as a fixed wall-time reporting threshold owned by the fast-check runner. At base the monotonic clock starts before root discovery, selection and target setup. The comparison is strict and sets a synthetic failure after the step loop (`rust/plangraph-cli/src/fast_checks.rs:287–321,353–418`). Measure the elapsed duration once immediately after the loop and compare it to `const WALL_BUDGET: Duration = Duration::from_secs(300)` in that file. Exactly 300 seconds has no overrun. Preserve every step's actual return code and seconds. Leave timeouts, selection and the first-failure stop in place.
- D2. An all-passing owned run over budget returns 0 after normal cleanup and publication, with `result green`, the ordinary exact-head local receipt ref, and one extra metadata line. A failed check returns 1 and produces no green receipt. Preserve the existing red local stamp and red local receipt commit for diagnostics. The brief's literal claim that failed checks currently write no receipt conflicts with the unconditional publication and its fixture (`rust/plangraph-cli/src/fast_check_worktree.rs:65–81`, `rust/plangraph-cli/tests/fast_checks.rs:334–359`). The published lane ref remains gated on a green receipt. Preserve operational errors, including cleanup or publication failure, as errors. The unowned command uses the same exit decision and reports timings to its streams. It writes child results only when the existing results path is supplied. The owned wrapper is responsible for the receipt (`rust/plangraph-cli/src/fast_checks.rs:316–320,401–418`, `rust/plangraph-cli/src/fast_check_worktree.rs:45–81`).
- D3. A breach adds one line `budget overrun wall_ns=<decimal elapsed nanoseconds> limit_s=300` to the child results file and the exact-head receipt. The suffix uses unsigned canonical decimal, positive limit and elapsed strictly greater than limit after conversion to nanoseconds. Emit the line last, after all real check rows. A green or red run that completes the step loop can report a breach. Preserve `check <label> rc=<i32> wall=<seconds to three decimals>` for each executed step, including the failing step if present. Reuse the existing receipt as the per-head timing report. The head-keyed shared stamp and local ref are replaced in place on rerun, and the pushed lane receipt carries one head's report across clones (`rust/worker-core/src/fast_check_stamp.rs:21–42,110–114,149–172,284–359`). No notification is enqueued. Under-budget reruns publish the latest measurement without an overrun line.
- D4. Keep stdout's selection, per-step wall lines and `fast-checks total wall seconds: <seconds to three decimals>`. Use one sample per step for the log and the stored timing. Preserve stderr's `WARNING: fast-checks exceeded the 300 second budget`, formatting the limit from `WALL_BUDGET`, once per over-budget execution. A real failure still prints `fast-checks: failed: <failed check label>` and the existing owned-worktree parent status message. A budget-only breach prints neither failure line. The exact-head receipt is the durable report. The warning is command output and may recur on an explicit rerun.
- D5. The supplied 2026-11-25 dell pr37 runs took 453, 490 and 395 s at load1 9.9, with `failed: pg-spawnd/test, budget`. The 2026-11-26T14:26Z workstation WSL feeder run `run-f2217d6e` logged `failed: pg-worker/test, budget`, spent two writer turns and left the head unpushed about 70 min. Those logs also record real check failures, which this item preserves.
- D6. The supplied 2026-11-26T18:33Z workstation WSL head `ee3afae7c` on 32 cores at load1 about 10 with a warm Cargo slot already accumulated about 690 s of green steps before the last step. The durations were pg-spawnd/test 177.5, pg-worker-core/test 148.3, plangraph-cli/test 111.9, pg-worker/clippy 97.5, pg-hook/test 25.0, pg-ctx/test 22.3, og-memory/test 20.5, pg-policy/test 18.3, scrub 12.6, and under 10 s apiece for the rest. The stamp lists every Rust crate in that selection. The same day's K1 runs `run-855e35a2` and `run-8c6a9ee7` each logged `failed: budget` twice with no failed check listed. A small workstation head took 24 s. The workload can exceed 300 s even in a warm slot. CPU or load scaling and host migration cannot guarantee a green receipt for every passing selection.
