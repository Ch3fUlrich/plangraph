# LE-PG-SPAWND-TESTS-FAIL-ON-THE-WORKSTATION-IN-FULL-FAST-CHECK-RUNS

Outcome. A native writer on a loaded work host earns its exact-head green fast-check stamp and reaches review. A failing check gives the same writer session its test names and panic output.

## Decisions

- D1. Keep the real sandbox as explicit live acceptance. Isolate ordinary readiness tests from user Git, client configuration and sandbox startup.
- D2. Resolve clients and session listings only from fixture inputs. Exercise the real resolution and stop decisions with private client paths and process inventories.
- D3. Use one injected feeder tick time and fixture disk/CPU inputs. Keep selection, quota file parsing and RAM accounting on the production path.
- D4. Keep complete failing streams in the exact-head log, the failed run record and the follow-up. Count named live skips in the native stamp.
- D5. Replace scheduler-dependent fixture ordering with a synchronization event or an injected clock. Preserve assertions and real process/HTTP boundaries where those are the subject.
- D6. Skip the process-crash acceptance only in the fast-check worker test invocation. Keep it mandatory in the existing Temporal-backed full suite and hold the timer open until the test releases it.

The supplied 2026-11-27 measurements record three standalone `cargo test -p pg-spawnd --no-fail-fast` passes of 1,020 tests at load 7–10 with one live Codex session. In the preceding 20 hours of native writer runs, `pg-spawnd/test` returned 101 in four runs, `affected-tests` returned 1 in five, and `og-memory/test` and `pg-worker/test` returned 101 once each. A writer can exhaust the unchanged-HEAD retry budget and end `no_commit` before review (rust/pg-spawnd/src/native_writer.rs:470–516). These counts establish symptoms. Except for the reported empty-list assertion, missing stdout leaves the individual panic causes unconfirmed.
