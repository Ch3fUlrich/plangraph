# LE-WRITER-COMPLETION-REASON-UNBOUNDED

Outcome. A terminal run record keeps `reason` and `completion.reason` within 4096 bytes plus a marker that names its bounded log file (`reason.log`, or `completion_reason.log` for a distinct completion reason), which keeps at most the first and last 512 KiB of the text in the run directory.

## Decisions

- D1. Bound: `REASON_KEEP_BYTES = 4096` and `REASON_LIMIT_BYTES = 4192` in both writers. A reason whose UTF-8 encoding is at most 4192 bytes is stored unchanged and writes no file. A longer reason is stored as its head, then the marker `\n[... <N> bytes omitted; see reason.log ...]\n`, then its tail. The head is at most 1024 bytes, cut by moving the end back to a UTF-8 character boundary. The tail is at most 3072 bytes, cut by moving the start forward to a character boundary. N is the decimal count of bytes between them. So head plus tail is at most 4096 bytes, and the marker is at most 73 bytes (a 20-digit N and the longest name, `completion_reason.log`, or the D7 text). A bounded reason is therefore at most 4169 bytes, below the 4192 trigger, and a re-save never bounds it again. The head shows the failing command and the tail shows the final error.
- D2. Log file, bounded (coordinator decision 2026-11-27): `reason.log` goes in the run directory (the parent directory of `record.json`), written with the existing atomic private writer and mode 0600. `REASON_LOG_KEEP_BYTES = 512 * 1024`. A failure text of at most 1 MiB (2 × 512 KiB) is written whole. A longer one is written as its first 512 KiB, then the one-line marker `\n[... <N> bytes elided ...]\n`, then its last 512 KiB, where N is the decimal count of dropped bytes. Both cuts move back to the nearest UTF-8 character boundary. The record gets `"reason_log": "reason.log"`, a relative file name only, so redaction and moving the run directory keep it valid.
- D3. Idempotent. A bounded reason never re-triggers (D1). The in-memory native record can still carry the raw text into a later `Host::save`, because `Host::save` bounds a clone. In that case the bounded text comes out the same, and the log write is skipped when `reason.log` already holds exactly the bytes about to be written (compare the length first, then the content). A reopen clears the pointer (D6).
- D4. One implementation per writer. The native writer (Rust) writes its record without passing through Python, and Python spawner runs never pass through Rust. Rust gets one pure function in a new lib module, `pg_spawnd::reason_bound`. Python gets one function, `keep_reason`, in `spawner/stderr_capture.py`. Both use the constant, marker text and file name from D1 and D2. The Python and Rust tests assert the same marker text.
- D5. Where each bound runs. Rust: `Host::save`, before `lifecycle::publish`. Every native writer terminal path goes through it, `finish` and `execute_request`'s configure refusal included. Python: `SpawnService._save`, directly after `record.update(clean(record))`, so the logs hold redacted text. That covers the native finisher in `overflow.py:671–678`, which re-saves the Rust record and can add a 4096-character tail reason. Python bounds `record['reason']` and, when `record['completion']` is a dict, `completion['reason']`, each on its own. A completion reason equal to the record's raw reason uses the record's bounded text and shares `reason.log`. A different long completion reason (for example the native `error` fallback in `notify.completion_event`) is bounded with the same D1 rule into `completion_reason.log`, with `completion['reason_log'] = 'completion_reason.log'` and the marker naming that file. Each log has its own D2 cap, so a run keeps at most two logs of 1 MiB plus marker each. The two refusal writes in `native_writer_commands.rs` (work-disk error and card sandbox refusal) store short fixed messages and stay unchanged.
- D6. Reopen. `reason_log` joins `SAVED_REOPEN_FIELDS` and `RESUME_REOPEN_FIELDS` in `native_writer.rs`, so a resumed run that ends with a short reason carries no pointer to an earlier outcome. The old `reason.log` file stays on disk; no record points at it.
- D7. Log write failure. A failed log write never blocks the terminal record. The reason is still bounded, but its marker reads `\n[... <N> bytes omitted; reason.log unavailable ...]\n` and no `reason_log` field is set. The save then proceeds. Python logs one warning naming the run id; Rust prints one line to stderr.

### Implementation

- Rust `reason_bound.rs`: `pub const REASON_KEEP_BYTES: usize = 4096; pub const REASON_LIMIT_BYTES: usize = 4192; pub const REASON_LOG_KEEP_BYTES: usize = 512 * 1024; pub const REASON_LOG: &str = "reason.log";` `pub fn bound(text: &str, log: Option<&str>) -> Option<String>` returns `None` at or below the limit; `log` names the file in the marker, and `None` produces the D7 marker. `pub fn log_text(text: &str) -> Cow<str>` applies D2. `pub fn bound_record(record: &mut Value, run_dir: &Path)` never fails. When `record["reason"]` is a string above the limit, it writes `log_text` per D3 and sets `reason` and `reason_log`, or applies D7 on a write error. Any other value is left unchanged. Register it with `pub mod reason_bound;` in `lib.rs`.
- `Host::save`: after cloning the record and before `lifecycle::publish`, call `pg_spawnd::reason_bound::bound_record(&mut record, self.record_path.parent().ok_or("record directory missing")?)`. `native_writer.rs`: add `"reason_log"` to both reopen field lists (D6).
- Python `stderr_capture.py`: `REASON_KEEP = 4096`, `REASON_LIMIT = 4192`, `REASON_LOG_KEEP = 512 * 1024`, `keep_reason(text, log) -> str | None`, `reason_log_text(text) -> str` (D2), and `bound_reasons(record, run_dir)`, which applies D1, D3, D5 and D7 and writes with `atomic_write_private`. In `SpawnService._save`, call `bound_reasons(record, self._path(record['run_id']).parent)` on the line after `record.update(clean(record))`.
- Docs: the fragment states the bound, the marker, `reason.log` and `reason_log`. The changelog fragment is one line.
