## Decisions

- D1. Preserve the CLI values and current derivation. `Thresholds::validate` requires positive alarm bytes no greater than cleanup bytes. For total bytes T, the resolved alarm is max(configured alarm bytes, floor(T × 25 / 100) + 1) and the resolved cleanup floor is max(configured cleanup bytes, floor(T × 20 / 100) + 1). Defaults are 5 GiB and 10 decimal GB respectively. Compare available bytes strictly below the resolved floor to start cleanup, and stop pressure eviction once available bytes reach that floor. At the percentage default this requires strictly more than 20% free. The 85%-used watchdog uses its separate strict comparison and remains the live safety ceiling. Use the existing flags and cap, with no new threshold knobs. [rust/worker-core/src/disk_hygiene.rs:65–96; rust/worker-core/src/bin/pg-disk-hygiene.rs:39–55,157–168; rust/worker-core/src/disk_runtime.rs:48–62; rust/worker-core/src/disk_watermark.rs:45–57]
- D2. Use one device-scoped pressure plan and one per-path protection check, shared with the existing cleanup helpers. A healthy device cannot satisfy a hot device's floor. Group canonical roots by `st_dev`, and key candidate identity by canonical path plus `(dev, ino)`. Rank eligible removal units by decreasing measured bytes or measured lower bound, then ascending canonical path. Confirm free space on each device after every successful removal and at the end. An overlapping subtree is credited once. [Existing entry points and accounting: rust/worker-core/src/bin/pg-disk-hygiene.rs:108–144,157–185,262–302; rust/worker-core/src/disk_hygiene.rs:19–63; rust/worker-core/src/disk_runtime.rs:46–62]
- D3. Set the linked-worktree `rust/target` idle interval N to 30 minutes. A stopped session means its recorded owner, if present, is terminal under `sweep_runs::finished` and has no survivors. For an unrecorded or idle session require every entry in the target to be older than the 30-minute cutoff. A stopped session makes its artifact rebuildable; the 30-minute young-file guard still protects any recently written cache, including one from a stopped session. An unfinished record retains ownership even when its output is quiet. Never infer a stopped owner from a Git commit timestamp. [rust/worker-core/src/private_targets.rs:107–130,147–179; rust/worker-core/src/disk_hygiene.rs:109–171; rust/worker-core/src/sweep_runs.rs:17–32,44–74]
- D4. In apply, queue one event per device below its cleanup floor with zero reclaimed bytes and exit 1. On a device with positive reclaimed bytes and final free space below its alarm floor, queue a partial-progress alert and set `alarm:true`. That condition alone exits 0. Use the final free-space sample for both decisions and preserve operational failures. Dry runs report kept reasons and projected removals without pressure events or pressure-driven failures. [rust/worker-core/src/bin/pg-disk-hygiene.rs:342–378; rust/worker-core/src/disk_runtime.rs:10–25; docs/stall-watchdog.md:32–44]
- D5. Incident evidence, supplied by the operator on 2026-11-26. The 32-core workstation WSL had a 1,081 G root disk. With about 15 Cargo builds, free space fell from 108 G at 14:30Z to 12.0 G at 15:24Z, about 2 G/min. Thirty-minute timer invocations took 10–46 minutes. The runs ending 15:27Z (34.7 G free) and 15:43Z (12.56 G free, alarm true) freed zero and said “build running: cache cleanup deferred”. The exception that afternoon ended 14:19Z (50.3 G, 51 actions). Approximate alarm and cleanup floors were 270 G and 216 G. The affected outputs were private `CARGO_TARGET_DIR` paths such as `$HOME/.cache/<session>/target-<lane>`, pool slots, nine linked `rust/target` trees totaling about 50 G, and 118.9 G of `/tmp` build directories at 15:43Z. The separate worktree-sweep dry run held 390 paths with “claims reader unavailable” and its timer was disabled. The main timer does skip multiple cleanup passes on a host build, but idle pool slots can already trim under their own leases. The 75% stderr line also coexists with a persisted report and the separate 85% watchdog input. [deploy/systemd/pg-disk-hygiene.timer:4–6; rust/worker-core/src/bin/pg-disk-hygiene.rs:137–144,157–195,282–302,357–376; rust/worker-core/src/disk_watermark.rs:139–160,173–199; rust/worker-core/src/sweep_facts.rs:129–152]

  While about 15 builds are active, the pass can reclaim idle linked `rust/target` trees older than 30 minutes, recognized idle targets in `/tmp` and per-session home caches, and eligible idle pool artifacts. Each live build's own target is busy. At 12.56 G free against an approximately 216 G cleanup floor, reclaiming only the idle portion can leave the device under both floors. D4 sends an alert for partial reclamation that ends below the alarm floor. Keeping root usage below 85% during sustained growth depends on the fill-rate item in N1.

- Per-path guards and removal. Match paths component-wise as equal to or descended from the owning scope. For linked-tree cache removals the scope is the linked tree plus its target; for an external private target, shared cache or pool slot it is the canonical target or slot root; use the main target itself for the special main-checkout pass. For example, `target-a2` is outside `target-a`. A Cargo allocation rooted at the slot protects its children; a generic cwd in an ancestor such as the cache parent does not protect unrelated children. Use the existing pin overlaps and nonterminal-run checkout/attempt overlaps, preserving the special main-checkout exception for a unit's reference to the checkout root; a pin explicitly naming the main target or anything inside it still protects. Give held leases and pins their own reason. Before reading a target recursively, use its existing nonblocking canonical sibling flock, or the existing in-directory lease for an affected scratch run. Preserve the lock through final checks and removal, and never unlink a sibling lease file. For slots use the same flock as acquisition, and also keep a valid named slot lease with a live owner; apply the existing slot lease liveness predicate without reaping sidecars in hygiene.
