## Decisions

- D1. Preserve the CLI values and current derivation. `Thresholds::validate` requires positive alarm bytes no greater than cleanup bytes. For total bytes T, the resolved alarm is max(configured alarm bytes, floor(T × 25 / 100) + 1) and the resolved cleanup floor is max(configured cleanup bytes, floor(T × 20 / 100) + 1). Defaults are 5 GiB and 10 decimal GB respectively. Compare available bytes strictly below the resolved floor to start cleanup, and stop pressure eviction once available bytes reach that floor. At the percentage default this requires strictly more than 20% free. The 85%-used watchdog uses its separate strict comparison and remains the live safety ceiling. Use the existing flags and cap, with no new threshold knobs. [rust/worker-core/src/disk_hygiene.rs:65–96; rust/worker-core/src/bin/pg-disk-hygiene.rs:39–55,157–168; rust/worker-core/src/disk_runtime.rs:48–62; rust/worker-core/src/disk_watermark.rs:45–57]
- D2. Use one device-scoped pressure plan and one per-path protection check, shared with the existing cleanup helpers. A healthy device cannot satisfy a hot device's floor. Group canonical roots by `st_dev`, and key candidate identity by canonical path plus `(dev, ino)`. Rank eligible removal units by decreasing measured bytes, then ascending canonical path. Confirm free space on each device after every successful removal and at the end. An overlapping subtree is credited once. [Existing entry points and accounting: rust/worker-core/src/bin/pg-disk-hygiene.rs:108–144,157–185,262–302; rust/worker-core/src/disk_hygiene.rs:19–63; rust/worker-core/src/disk_runtime.rs:46–62]
- D3. Set the linked-worktree `rust/target` idle interval N to 30 minutes. A stopped session means its recorded owner, if present, is terminal under `sweep_runs::finished` and has no survivors. For an unrecorded or idle session use more than 30 minutes since the newest mtime in the target as the activity evidence. A stopped session makes its artifact rebuildable; the 30-minute young-file guard still protects any recently written cache, including one from a stopped session. An unfinished record retains ownership even when its output is quiet. Never infer a stopped owner from a Git commit timestamp. [rust/worker-core/src/private_targets.rs:107–130,147–179; rust/worker-core/src/disk_hygiene.rs:109–171; rust/worker-core/src/sweep_runs.rs:17–32,44–74]
- D4. Use exit 1 for apply-mode zero progress on any device still below its cleanup floor at the final sample. Persist the report and one existing-watchdog outbox event per such device. Dry runs report the same kept reasons and projected removals and raise no zero-progress event or failure. Ordinary probe and reporting errors keep their nonzero behavior. [Existing CLI/report contract: rust/worker-core/src/bin/pg-disk-hygiene.rs:342–378; rust/worker-core/src/disk_runtime.rs:10–25; docs/stall-watchdog.md:32–44]
- D5. Incident evidence, supplied by the operator on 2026-11-26. The 32-core workstation WSL had a 1,081 G root disk. With about 15 Cargo builds, free space fell from 108 G at 14:30Z to 12.0 G at 15:24Z, about 2 G/min. Thirty-minute timer invocations took 10–46 minutes. The runs ending 15:27Z (34.7 G free) and 15:43Z (12.56 G free, alarm true) freed zero and said “build running: cache cleanup deferred”. The exception that afternoon ended 14:19Z (50.3 G, 51 actions). Approximate alarm and cleanup floors were 270 G and 216 G. The affected outputs were private `CARGO_TARGET_DIR` paths such as `$HOME/.cache/<session>/target-<lane>`, pool slots, nine linked `rust/target` trees totaling about 50 G, and 118.9 G of `/tmp` build directories at 15:43Z. The separate worktree-sweep dry run held 390 paths with “claims reader unavailable” and its timer was disabled. The main timer does skip multiple cleanup passes on a host build, but idle pool slots can already trim under their own leases. The 75% stderr line also coexists with a persisted report and the separate 85% watchdog input.
