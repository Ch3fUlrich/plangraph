# LE-NATIVE-LAUNCH-ADMITS-NO-ITEM-AND-REFUSES-THE-WRITERS-COMMITS-LATER

Outcome. A native Codex launch whose brief names item keys the writer could not commit, or that admits no key at all, is refused at lane admission with the `Plan item:` hint. The commit gate and the reviewer use exactly the admitted keys. A `review_dir` is claimed atomically by one live run, and feeder runs get their own `review_dir`.

## Decisions

- D1. Admitted keys bind the gate (item step 2). Add `Host::assigned_keys(&self) -> Vec<String>` in `native_writer_review.rs`. It reads the run record at `self.record_path` (`records::read_record_file`). When the record has `lane_admitted: true`, the result is its normalized `item_key` followed by its `item_keys`, de-duplicated in that order. These are exactly the keys lane admission wrote into the request card and the supervisor published. A record without the mark (a run started before this change) keeps today's set, `item_keys(&self.brief)`, plus its `item_key`. `check_item_trailers`, `skipped_items` (given the key list instead of the brief), `brief_context` and the review card's single-item choice (lines 35, 170, 203 and 352) all use `assigned_keys`. A card-only key then passes the trailer gate, and a body-only heading of a typed input fails it. `Host::configure` still appends one `Plan item: <key>` line for each assigned key that the rendered brief's `item_keys` lacks, so the writer prompt names its keys. That line is for the writer only; the gate reads the record.
- D2. Launch refusal (item step 1). In `admit_lane`, after `admit_launch` returns the admitted keys, the launch is refused as `no_admitted_item`. The label check runs first. (b) Unless the brief is a typed batch input (`batch_writer_brief::typed_keys` is `Some`), item label lines that name a valid key outside the admitted set refuse with `no_admitted_item: use 'Plan item: <key>' lines; not admitted: <k1>, <k2>`. (a) Only then, an empty admitted set refuses with `no_admitted_item: the brief and card name no item key; use 'Plan item: <key>' lines`. A label line is a line that, after trimming leading spaces and an optional `- ` or `* ` bullet, starts case-insensitively with `item:`, `items:`, `item keys:`, `plan items:`, `plan-item:`, `key:` or `keys:`. Its keys are the tokens after the label, split on whitespace, `,`, `;` and `|`, stripped of surrounding backticks, quotes and one trailing `.`, that pass `valid_key`, then normalized. A label naming a key the card admits passes. The item's "fewer keys than the card names" case is covered by D1: card keys are always admitted, so a brief that names fewer keys strands no work.
- D3. Review directory (item step 3), in two layers. Early check: in `admit_lane`, after D2, when the card has a string `review_dir`, the launch is refused with `review_dir_in_use: <dir> is used by live run <name>` if a run record that `lane_guard::scan_runs` reports as holding (live implement) has an equal `review_dir`. Two paths are equal when both canonicalize to the same path, or else when their lexical components are equal. Atomic claim: `execute_request`, before `Host::configure`, claims the effective review directory (record, then card, then default, as `from_request` resolves it). It creates the directory and then `<review_dir>/.run-claim` with `create_new`, holding the run id. On `AlreadyExists` it reads the owner id. The run's own id (a resume) passes. A live owner, meaning its record exists and `lane_guard`'s liveness says it holds, refuses the run: a terminal `refused` record with exit 5 and the `review_dir_in_use` reason. An owner whose record is missing or finished is stale: the claimant removes the claim file and retries `create_new` once, so of two concurrent claimants exactly one wins. The claim is never released explicitly; staleness is decided by the owner's liveness.
- D4. Feeder runs get their own directory. `feeder::workflow::batch_card` sets `review_dir` to `<reviews>/<status file stem>`. The status path is already allocated exclusively per launch, so the directory is unique per run and parallel feeder launches no longer collide.
- D5. Stable reasons. `lane_admit::REASONS` becomes `["lane_unreadable", "lane_collision", "lane_too_many_keys", "no_admitted_item", "review_dir_in_use"]`, and Python `_LANE_REFUSALS` gains `'no_admitted_item:'` and `'review_dir_in_use:'`. Remote launches then report the hint text instead of `target rejected admission`.
- D6. Code placement. `unadmitted_brief_keys`, `with_card_keys`, `refuse_review_dir` and `claim_review_dir` go in a new bin module `rust/pg-spawnd/src/launch_admission.rs` that uses the public `pg_spawnd::lane_guard` functions. `lane_guard.rs` and its tests stay unchanged; LE-SPAWND-ONE-OVERSIZE-RUN-RECORD-BLOCKS-THE-LANE edits those files, and its projection keeps `review_dir` for the early check.
- D7. Docs (item step 4). `docs/native-codex-writer.md` gets a "Brief item lines" paragraph naming the four accepted forms, the D1 rule, both refusals and the review directory claim. The spawner fragment states D5.
