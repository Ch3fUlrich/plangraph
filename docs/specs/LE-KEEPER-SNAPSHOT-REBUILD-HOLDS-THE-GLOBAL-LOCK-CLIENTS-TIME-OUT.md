## Decisions

- D1. D-6969 rule 3.100(8) and D-6970(2) put this existing p10 item first and require workstation heavy checks, one batch K GPT writer, and independent design approval before a claim. Planned read-after-write contract is committed graph state for API reads and bounded asynchronous staleness for the derived file.
- D2. Incident baseline: 133 writer-timing rows, 756,866 ms total hold and a 24,387 ms peak. One whoami waited 12,127 ms. The old timings cannot identify its blocker, and nearby cancel and snapshot holds both merit investigation. There were 125 non-message request rows over 15 seconds. Request hold_ms > 2,000 grouped by verb was cancel 209, messages 482 (includes mis-accounted polling wall time), create_items 4, edit_definition 2, apply_ops 1. Values come from the retained incident window; do not treat all long holds as snapshot-caused.
- D3. Canonical direct Keeper show confirms open, no dependencies and no design_ref. Its done criteria also require message poll and merge-index lock isolation. The protected source already releases the timed lock for fleet projection, publication and file IO (snapshot_io.py:26–78), and authenticated normal GET show/ready/snapshot already use an MVCC store (api.py:58,144–148,210–232,667–692). Any improvement is measured on configured writer/reaper/startup/sync paths.

## Scope and reuse

- R1. Configured capture. At entry to snapshot_io.write_snapshot choose committed mode solely from configured read_path and existing backend/schema/DSN selection. Drop only the instrumented request/reaper lock with timing.outside_request_lock, then take a per-server capture mutex before creating the independent read transaction. Never wait on the capture mutex while holding server.lock; leave the mutex before the outer timing context reacquires the lock. Move daemon startup's raw nested server.lock away for this path. Use read_store's independent connection, detached Store view and audit deferral; capture graph and persisted fleet host registry within the same transaction. Close reader before fleet file IO, JSON/sign/rename, and keep the capture mutex through publication. Preserve system/run-token handling, previous principal audit attribution where allowed, and old single-threaded/shared Store serialization only for explicit no-read-path fixtures or embedded callers. A configured reader failure never takes that branch; it leaves the last valid publication and is retried by the existing writer/reaper lifecycle.
- R2. Preserve existing ticket/publish API, but reserve configured tickets only inside the capture mutex, then carry that ticket through the existing signing/publication fence. All configured producers use this one seam so an older capture cannot publish after a newer capture. SnapshotPublication.latest advances only on successful full pair publication. Optional fleet projection still reports its existing fixed failure state. No source lock is reacquired while holding capture mutex, except the existing nonblocking read-audit fast path; queued audit delivery owns the global lock independently. Keep failed committed-reader handles closed and whole snapshot shape/epoch, detached-signature order, verified-reader retry, pull monotonic-head guard and startup recovery.
- R3. Writer has one automatic worker and one exclusive build gate shared with flush. Capture covered generation after entering the gate and before the first committed read. Preserve first/latest timestamps of marks newer than cutoff. Success retires only the covered generation; failure restores pending ages and leaves coverage unchanged. Automatic attempt starts no sooner than completion of the preceding attempt plus max(configured debounce, prior attempt duration), including failures. Use separate monotonic deadlines for debounce/max_delay and gap, then take the later. This bounds consecutive automatic capture duty cycle by 50% per completed attempt under continuous load, excluding startup/explicit flush/zero-debounce compatibility. A pending mark is selected after at most max_delay plus its interrupted build and its finite gap, and the selected build publication adds its own duration, absent failures. A one-shot flush does not sleep for the background gap, covers at least its entry generation, and leaves newer marks pending. Reaper and startup semantics remain; the staleness doc must state the revised formula, failure and explicit-flush exceptions. Duration-based gap is an EXPERIMENT against natural incident duty cycle and catch-up; do not silently loosen signed-file freshness needs.
- R4. Preserve local signed-file behavior and update staleness plus the item-specific docs fragment. Source net budgets on the protected base: api.py +2, timing.py +95, snapshot_io +45, snapshot_writer +78, daemon +12, api_routes +65, messages_poll +45. Test net additions at most 100 snapshot, 75 timing, 70 merge refresh and 80 messages. Use existing files and 800-line cap. api.py is intentionally shared with the later K2 draft, +5 additional lines reserved there, aggregate 793+2+5=800. One writer, K1 and K2 strictly serial. Re-run both sets on the final combined head.
- N1. Preserve read auth and visibility, avoid shared-connection unlock, schema, signed format, publication cache for live GET, new source language exception, service or rollout change. No configured DB read fallback to shared Store. Every src/plangraph/keeper path is an AUTH_DOOR path. These files require an actual writer, HIGH review and routing GO. The ordinary auto-GO helper refuses them as protected. They match neither ci_commit_gate.GATE_PATHS nor go_verify OPERATOR_CLASS, so those two gates do not by themselves require a Gate-Edit grant. If later route/classification or scope changes, obtain the exact grant before editing any newly gated path. Pure source diff and live rollout are distinct approvals.

- R5. Configured messages keep only initial global auth, drop the outer timer while LISTEN setup, waiting and independent fresh committed reads run, and avoid reacquiring after auth on the success path: after the initial timed auth and before the legacy timed dispatch, _handle hands configured normal GET messages to an api_routes helper through an exact two-line branch; API wrapper and auth-timer substitutions are net-zero. Use read_store(defer_audit=True) for each configured poll so its existing audit queue avoids the fast-path global try-lock; add the optional keyword and guard through net-zero API line substitutions. Preserve revocation checks for every store read, lost NOTIFY fallback, bounded deadline/listener cap and all existing filters, modes and roles. Legacy no-reader and mutable oversight may take a timed lock for individual authorized reads, never across a poll wait. X7 counts the production configured requests, including their actual audit path.
- R6. Merge refresh. Use a short configured read_store block to materialize merge_candidates and _deploy_inputs, then close it. Use a detached Store copy with conn disabled for warm_merge_scan: _snapshot_deploy uses pre-read _deploy_inputs and Git/forge, and _snapshot_landing_decisions uses the decision adapter. Deep-isolate mutable _named_landings plus _landings and prior warm maps so a failed scan never leaks. The short projects control lookup follows the same committed read seam. Give each warm scan its own mapping of all mutable caches. The scan and sole-worker budget of 180s run without the global lock or an open DB transaction. Publish complete bundle under a private mutex only, after deadline/generation verification. Close's existing consume call installs the selected immutable-by-ownership bundle while its own mutation holds the global lock. Include _named_landings in the same bundle and retain authoritative close rechecks. Avoid private-lock/global-lock inversion; handle missing configured reader only in explicit fixture compatibility.
- R7. Implement holder and auth timing in timing.py. Wrap keeper's RLock internally with bounded 512 recent outermost hold intervals per server lock, preserving acquire/release and blocking/reentrant semantics. At outermost release, append the completed interval before unlocking and capture label, acquisition and release times for accounting behind writer_timing, snapshot_timing, messages, merge refresh and other fixed verb labels. Intersect a wait's monotonic interval with completed outer hold spans after acquisition, report actual holder and coverage; classify raw untimed owners as unclassified, emit overflow/unattributed explicitly, and never log request fields or secrets. Use timed tagged phases for merge and messages, not raw release/acquire. Cap metadata and emit after the source lock. Wrap the initial legacy auth block with a timing helper so refusals and blocked whoami emit phase=auth wait_ms and separate request hold; apply the committed messages handoff without another global dispatch acquire. Single api.py net +2 by same-line substitutions or compact reuse. Distinguish auth samples from request totals in aggregation. Preserve hardware/fixture latency measurement separately.
