# LE-KEEPER-SNAPSHOT-REBUILD-HOLDS-THE-GLOBAL-LOCK-CLIENTS-TIME-OUT

Outcome. Publish coherent Keeper snapshots without holding the global request lock for the configured production rebuild.

- plan_source. Plan-roadmap signed fleet-bus sequences 714 and 715, batch K and incident, and sequence 780, final K1 design ruling. Protected authority D-6969 rule 3.100 and D-6970(2) (protected data PR 771). Round 3 revises scrubbed predecessor 5b4a2abb after independent review.

- evidence_after_deploy. Live: Retain a two-hour production window with reviews active and at least 100 successful automatic configured writer builds. K1 passes when there is no global-lock hold over 2 seconds by writer, snapshot, messages or merge refresh, and no wait over 2 seconds whose primary attributed holder is in those groups. Apply R8's per-wait coverage and overflow rules. Report writer p95 global hold against 250 ms, compare query_ms and staleness, and report overall waits over 2 seconds and client timeouts by observed holder or explicit unknown. Other fixed holder groups do not fail K1. The filed cancel follow-up is plangraph:LE-KEEPER-CANCEL-HOLDS-THE-GLOBAL-LOCK-WHILE-IT-VALIDATES-THE-WHOLE-GRAPH.

## Decisions

- D1. D-6969 rule 3.100(8) and D-6970(2) put this existing p10 item first and require workstation heavy checks, one batch K GPT writer and independent design approval before a claim. Seq780 requires criterion R8 and separates the filed cancel sibling from K1. API reads still come from committed graph state and the derived file has a bounded asynchronous contract.
- D2. The verified incident has 133 writer timing rows over about 150–155 minutes, 756,866 ms total hold and a 24,387 ms peak. This is about 103–106 rows per 120 minutes; 100 successful automatic builds is a comparable minimum, rounded down modestly. There were 125 non-message request rows over 15 seconds. Request hold_ms > 2,000 grouped by verb was cancel 209, messages 482 (includes mis-accounted polling wall time), create_items 4, edit_definition 2 and apply_ops 1. One whoami waited 12,127 ms; old timing lacks direct blocker attribution.
- D3. Canonical direct Keeper show confirms open, no dependencies and no design_ref. Its done criteria also require message poll and merge-index lock isolation. The protected source already releases the timed lock for fleet projection, publication and file IO (snapshot_io.py:26–78), and authenticated normal GET show/ready/snapshot already use an MVCC store (api.py:58,144–148,210–232,667–692). Any improvement is measured on configured writer/reaper/startup/sync paths.

## Scope and reuse

- R1. Configured capture uses the existing read_store with audit deferral, on the configured store's backend and source (SQLite WAL read-only BEGIN and matching DB file, or PostgreSQL REPEATABLE READ READ ONLY and the writer schema/DSN). Do not access the writer connection from the independent capture. Capture items, evidence, aliases, head and persisted fleet host rows in the same transaction, then close it before fleet projection, signing and rename. Opening/validating a configured reader must fail closed if unavailable, wrong backend/schema/source or not a distinct committed reader; never fall through to the shared Store. Validate the route and backend using existing server construction and DB helpers, and assert the actual SQLite/PG receipt in the tests. Preserve system/run-token handling and audit attribution; hand captured read audits to the existing queue without a fast-path acquire of G. Read work is now outside G; an external authority on a real committed update remains the Store.
- R2. Keep the existing publication ticket API and detached signature order. For configured sources, reserve the ticket after entering C; optional fleet projection and full publication happen under C, with P taken only for the existing sign/replace fence. On an error before publication or a failed replace, latest and writer generation do not advance, so the pending request remains retryable. Do not serve unverified local copies in the signature/body gap. The reader closes before P; release P then C before any G reacquisition, and never enter G for audit from B/C/P. Signing failure retains current fail-closed semantics.
- R3. One automatic worker and one configured B shared with flush. Sample the covered generation under D just after B and before the first reader query, retaining original first/latest marks newer than cutoff. Retire the cutoff only on complete success, and restore pending age on error. An automatic attempt starts no sooner than completion of the preceding attempt plus max(debounce, prior attempt duration), including failures. Take the later of the normal debounce/max_delay deadline and this monotonic gap. A healthy pending mark waits at most its in-progress build and finite gap plus max_delay and its selected build duration. This is a 50% automatic duty-cycle experiment, excluding startup, explicit flush and zero mode. Flush reads its entry generation under D and releases D before waiting for B. It may coalesce if that entry mark is already retired, otherwise captures at least through it once under B; no automatic gap applies to flush. Newer marks remain pending and stop retains bounded daemon shutdown/startup recovery. The staleness doc must spell out timing and failure exceptions.
- R4. Preserve local signed-file behavior and update staleness plus the item-specific docs fragment. Source net budgets on the protected base: api.py +2, timing.py +130, snapshot_io +70, snapshot_writer +100, daemon +16, api_routes +65, messages_poll +45. Test net additions at most 145 snapshot, 110 timing, 70 merge refresh and 80 messages. Use existing files and 800-line cap. api.py is intentionally shared with the later K2 draft, +5 additional lines reserved there, aggregate 793+2+5=800. One writer, K1 and K2 strictly serial. Re-run both sets on the final combined head.
- N1. Preserve read auth and visibility, avoid shared-connection unlock, schema, signed format, publication cache for live GET, new source language exception, service or rollout change. No configured DB read fallback to shared Store. Every src/plangraph/keeper path is an AUTH_DOOR path. These files require an actual writer, HIGH review and routing GO. The ordinary auto-GO helper refuses them as protected. They match neither ci_commit_gate.GATE_PATHS nor go_verify OPERATOR_CLASS, so those two gates do not by themselves require a Gate-Edit grant. If later route/classification or scope changes, obtain the exact grant before editing any newly gated path. Pure source diff and live rollout are distinct approvals.

- R5. Configured messages keep only initial global auth; LISTEN setup, waiting and independent fresh committed reads never enter the legacy dispatch timer or reacquire G on the success path: after the initial timed auth and before the legacy timed dispatch, _handle hands configured normal GET messages to an api_routes helper through an exact two-line branch; API wrapper and auth-timer substitutions are net-zero. Use read_store(defer_audit=True) for each configured poll so its existing audit queue avoids the fast-path global try-lock; add the optional keyword and guard through net-zero API line substitutions. Preserve revocation checks for every store read, lost NOTIFY fallback, bounded deadline/listener cap and all existing filters, modes and roles. Legacy no-reader and mutable oversight may take a timed lock for individual authorized reads, never across a poll wait. X7 counts the production configured requests, including their actual audit path.
- R6. Merge refresh. Use a short configured read_store block to materialize merge_candidates and _deploy_inputs, then close it. Use a detached Store copy with conn disabled for warm_merge_scan: _snapshot_deploy uses pre-read _deploy_inputs and Git/forge, and _snapshot_landing_decisions uses the decision adapter. Deep-isolate mutable _named_landings plus _landings and prior warm maps so a failed scan never leaks. The short projects control lookup follows the same committed read seam. Give each warm scan its own mapping of all mutable caches. The scan and sole-worker budget of 180s run without the global lock or an open DB transaction. Publish complete bundle under a private mutex only, after deadline/generation verification. Close's existing consume call installs the selected immutable-by-ownership bundle while its own mutation holds the global lock. Include _named_landings in the same bundle and retain authoritative close rechecks. Avoid private-lock/global-lock inversion; handle missing configured reader only in explicit fixture compatibility.
- R7. Track only outermost G ownership with the reentrant RLock wrapper. Retain the last 512 intervals per process/server in a bounded ring; record each under G immediately before native release, then emit after release. Snapshot relevant ring metadata after timed acquisition and compute overlap outside G. Keep RequestTimer's existing request/verb totals, and add fixed waiter phases for initial auth, main dispatch, supported reacquisition and maintenance. Use writer and snapshot at their own timed seams, messages at its known door, and merge_refresh for refresh control rather than ordinary close dispatch. Existing validated route verb names are labels for other handlers; allowlist additional raw maintenance labels. A single-line API timer substitution uses the helper label for refresh control. Wrap the auth block at its existing line so refused auth is timed too. Replace the audit flush and audit fast path wrappers in api.py with same-line tagged equivalents (read_audit); label host samples in daemon.py as host_samples and legacy startup as snapshot. Other raw holds stay intentionally unclassified unless already under an outer recognized owner; they never count as labelled coverage. Restore writer p95 global hold reporting relative to 250 ms. Budget: api.py stays net +2, timing.py up to +130, snapshot_io up to +70, snapshot_writer up to +100, daemon up to +16, tests snapshot +145 and timing +110. These caps match R4; K2 retains its separate +5 API limit.

- R8. Fixed payload-free timing. Emit `keeper: lock_wait phase=<auth|dispatch|reacquire|maintenance> waiter=<fixed-label> wait_ms=<integer> covered_ms=<integer> coverage_bp=<integer> overflow=<0|1> holder=<fixed-label|tie|none> overlaps=<label>:<ms>[,<label>:<ms>...]` using a single space between fields and no trailing space. `overlaps=-` means no labelled spans. Emit after release for each sampled auth phase and every wait >2,000 ms. Clip monotonic completed outer hold intervals to the acquisition window, sum each allowlisted group's overlap before integer truncation, and derive covered_ms from the union of labelled nanosecond overlaps, capped at wait_ms. Compute coverage_bp=floor(10,000*covered_ms/wait_ms) for wait_ms>0, otherwise 10,000. Use unique labels sorted lexically. `holder` is the largest positive reported overlap total by group, `tie` if equal, `none` if no known overlap; tie includes every co-primary in overlaps. Capture last-evicted end timestamp; if retained data omitted a span ending after wait entry, emit overflow=1 even if the observed coverage looks sufficient. No credentials, data, raw error details or arbitrary strings. Emit `keeper: lock_hold holder=<fixed-label> hold_ms=<integer>` for every relevant outer span and every other hold >2,000 ms. Emit one terminal `keeper: snapshot_build mode=automatic outcome=<ok|error> elapsed_ms=<integer> lock_hold_ms=<integer>` per configured automatic attempt even if its lock hold is zero, outside the lock. Count only complete ok events for Live. For each wait >2,000 ms in the window require coverage_bp≥9000 and overflow=0, and mark any ring overflow or missing request/source logs inconclusive. A confirmed relevant hold/wait breach is a failure even when other data is inconclusive. Primary attribution is the largest labelled overlap, with all tied primaries counted. Report overall waits and client timeouts by fixed group, including other known groups and explicit unknown (aggregate by primary; unknown when records cannot be safely joined). A fixed cancel attribution is known and informational. Track 512 capacity saturation as measured, not presumed.

- R9. Lock order, including lifecycle and reentrancy. Let G=server.lock, B=SnapshotWriter build gate, C=per-server configured capture mutex, P=existing publication lock, D=writer condition. The configured automatic worker and flush enter B at G depth zero; never take G inside B, including finalization, error handling or read-audit exit. Their build metrics use a lock-free timer. Under B the only permitted nests are short B→D and B→C→P. A mark already under G can briefly take D; D is never held while waiting for B, C, P or G, or across capture or IO. Condition.wait atomically releases D while waiting. Wakeups/cohort checks release D before waiting for B. Startup configured calls write_snapshot at G depth zero and acquires C→P directly. Shutdown's flush and stop likewise enter at depth zero, release D before joining and join with no G/B/C/P/D. Preserve the existing bounded shutdown caller lifecycle. Configured zero-debounce POST or reaper is the sole timed suspension path for configured snapshot publication. It completes the Store write, verifies the current RequestTimer owns this exact G at recursion depth one and the shared DB connection is out of transaction, suspends G, then acquires C→P (no B). Its return or exception releases P and C before restoring the timer and reacquiring G; no shared connection use during suspension. Check ownership at entry using the tracked RLock; never assume releasing one recursion leaves the lock free. Raw G ownership and depth >1, a missing/mismatched timer on an owned G, and an open shared transaction refuse synchronously before C or any suspend. Calls to configured flush/stop with any owned G fail before changing the lifecycle or entering B. The refusal preserves existing pending work and emits only a fixed diagnostic. Normal daemon/API paths must satisfy the precondition; do not unlock an unknown outer caller, run inside its transaction, or wait in the refusal path. For explicit no-read-path compatibility only, take G and keep it through the shared-store build; there is no B or C on that path, and P, when present, is downstream of G. Existing mock/no-lock callers are single-threaded. The merge-refresh private mutex remains separate: configured background never waits on G, and close may take it briefly under G only to install the completed bundle. Deferred audits execute via the independent queue and never acquire G from any capture or build lock.
