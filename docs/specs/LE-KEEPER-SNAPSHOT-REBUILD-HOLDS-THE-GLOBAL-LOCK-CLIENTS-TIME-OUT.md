## Scope and reuse

- R1. Configured capture. At entry to snapshot_io.write_snapshot choose committed mode solely from configured read_path and existing backend/schema/DSN selection. Drop only the instrumented request/reaper lock with timing.outside_request_lock, then take a per-server capture mutex before creating the independent read transaction. Never wait on the capture mutex while holding server.lock; leave the mutex before the outer timing context reacquires the lock. Move daemon startup's raw nested server.lock away for this path. Use read_store's independent connection, detached Store view and audit deferral; capture graph and persisted fleet host registry within the same transaction. Close reader before fleet file IO, JSON/sign/rename, and keep the capture mutex through publication. Preserve system/run-token handling, previous principal audit attribution where allowed, and old single-threaded/shared Store serialization only for explicit no-read-path fixtures or embedded callers. A configured reader failure never takes that branch; it leaves the last valid publication and is retried by the existing writer/reaper lifecycle.
- R2. Preserve existing ticket/publish API, but reserve configured tickets only inside the capture mutex, then carry that ticket through the existing signing/publication fence. All configured producers use this one seam so an older capture cannot publish after a newer capture. SnapshotPublication.latest advances only on successful full pair publication. Optional fleet projection still reports its existing fixed failure state. No source lock is reacquired while holding capture mutex, except the existing nonblocking read-audit fast path; queued audit delivery owns the global lock independently. Keep failed committed-reader handles closed and whole snapshot shape/epoch, detached-signature order, verified-reader retry, pull monotonic-head guard and startup recovery.
- R3. Writer has one background loop and one exclusive run/flush build gate; the condition is never held during DB or IO. Sample the covered mark generation after entering the build gate and before the first committed read. Track the oldest and newest mark newer than that cutoff independently from the active cohort; on success retire only the cutoff, and keep original pending timestamps; on failure restore the oldest timestamp of both cohorts and track a separate retry-not-before timestamp of one debounce interval. No spinning, parallel fallback, or repeated flush loop. Flush captures at least its entry generation, may coalesce a concurrent completed build, raises on error, and leaves later marks pending. Stop keeps current bounded join and startup re-derivation behavior. Zero-debounce synchronous caller waits for the same publication pipeline outside the source lock; a healthy configured writer allows one active capture, queued producers never start duplicate speculative reads. Reaper keeps revision dirty until successfully published or successfully handed to the debounced writer; while zero-debounce publication is out of the lock the pending ticket/revision remains retryable.
- R4. Preserve RequestTimer hold vs elapsed build and fleet/sign/write parts, and existing failure/recovery/alarm output. Update staleness contract and an item-specific docs/keeper fragment to satisfy .docs-map. Expected additions net ≤45 source lines per touched module except snapshot_writer up to 70, ≤95 snapshot test lines and ≤30 timing test lines, with repository file-size checks unchanged.
- N1. No shared-connection unlock, read auth or visibility change, schema, signed format, publication cache for live GET, new source language exception, service or rollout change. No configured DB read fallback to shared Store. Every src/plangraph/keeper path is an AUTH_DOOR path. These files require an actual writer, HIGH review and routing GO. The ordinary auto-GO helper refuses them as protected. They match neither ci_commit_gate.GATE_PATHS nor go_verify OPERATOR_CLASS, so those two gates do not by themselves require a Gate-Edit grant. If later route/classification or scope changes, obtain the exact grant before editing any newly gated path. Pure source diff and live rollout are distinct approvals.

- R5. Messages. In messages_poll.read_messages use timing.outside_request_lock, never raw release/acquire. Configured readers perform LISTEN setup, per-attempt committed reads, and sleeps outside the outer timed lock. Open and close a fresh read transaction per retry so a NOTIFY or polling timeout observes the next commit. Preserve deadline, listen cap, cursor order/dedup and token revalidation at Store.messages. Oversight/legacy no-reader paths restrict the shared lock to individual authorized reads; still release during listening/wait and account used intervals. Pass only immutable listener connection settings into outside-lock code, never use the shared writer connection for a query. Close LISTEN resources on all returns. Keep periodic lost-NOTIFY fallback and existing max 30s; exercise the auth and notification tests.
- R6. Merge refresh. Introduce one small private MergeRefresh mutex for state, used, expires_at and a detached published bundle. At start, copy the prior frozen detached cache reference under that mutex; no DB or Git while held. Build from server.read_store on one independent committed transaction through warm_merge_scan, including _snapshot_deploy queries, and retain existing one-worker and 180s budget. Publish detached immutable-by-ownership bundle only under the private mutex after final budget/generation check. On consume, used by the existing close entry under server.lock, install the complete bundle into that single close's live Store context and preserve commit/epoch/live proof verification. Keep last ready bundle for diagnostics on failure but make failed/expired state unconsumable. Never acquire server.lock from build or hold the private mutex while acquiring server.lock; committed-store audits use their existing queue and _build does not emit graph writes. The projects control read uses a committed store outside the outer timer lock as well. Recheck existing fixture fallback confined to mocks/no-reader setup.
- R7. Keep wait_ms for existing fast and slow timed verbs and separate elapsed from hold. Include auth-seat acquisition and emit all verb timings through existing timing.py if needed within the exact 7-line aggregate API headroom. api.py changes for trace seams are owned by K2 only; coordinate new seams before combined checks. Observe Postgres query-time and scheduler delay for show/ready/snapshot separately, without widening this lane to unrelated slow queries. Use a synthetic 10 s paused-capture fixture while verifying whoami and a real claim respond within 1 s; use deterministic barriers for local repeatability and run timed assertions on the workstation. Additional envelope +55 api_routes, +35 messages_poll and +18 timing, tests +80 aggregate.
