## Verified premise

- A durable runner already exists. `Runner::resume` validates and replays a prefix, and `StepLog` persists each attempted step before sending its journal row. Current `pg-spawnd steps` consumes a different stdin transport protocol. The binary dispatch has no batch-list command. (`rust/pg-spawnd/src/step_runner.rs:345–381,474–525`, `rust/pg-spawnd/src/step_runner_log.rs:71–89`, `rust/pg-spawnd/src/cli.rs:167–178,203–221`).
- The feeder is already live-capable and locally pinned. It claims before launch and starts the existing Python spawner path, which writes a private native request and invokes `native-writer`. No tracked feeder path dispatches the batch runner. D-6749 and the batch158 comparison come from the supplied plan graph brief. This tree contains no baseline turn series. (`rust/plangraph-cli/src/feeder/workflow.rs:248–288`, `rust/plangraph-cli/src/feeder/adapters.rs:308–365`, `src/plangraph/spawner/overflow.py:596–649`, `docs/writer-feeder.md:3–25`).
- The existing runner limit counts fixes, while the round cap rule counts reviews. The native rule allows eight reviews. The library default of eight fixes could allow nine reviews. (`rust/pg-spawnd/src/step_runner.rs:49–63,320–334,387–404`, `rust/pg-spawnd/src/round_progress.rs:18–19`, `rust/pg-spawnd/src/native_writer.rs:69–77,546–554,609–619`).
