## Decisions and entry points

1. The existing sibling `<target>.plangraph-lock` carries exclusion for that physical target. The Rust fast-check acquires an exclusive `SlotLease` with `fast_check_target::resolve_cargo_target` and `cargo_pool::acquire_slot`. Pool slot 0 is primary and later slots live beneath the pool directory. Rust exports the actual slot as `CARGO_TARGET_DIR`. Python `shared_cargo_target` reads `PLANGRAPH_CARGO_TARGET_DIR`. The reproductions concern a coincident physical target. The slot metadata file remains metadata.
2. POSIX contention comes from `EAGAIN`/`EWOULDBLOCK` from nonblocking `flock` on the open file. Windows contention comes from `ERROR_SHARING_VIOLATION` under the existing `CreateFileW` share mode. Unrelated I/O and permission failures keep their OS cause. A display string or persisted PID has no authority.
3. Use a probe's absolute monotonic deadline and its own launch state. Mark the transition synchronously immediately before invoking the real process factory. Subprocess creation in flight qualifies as dispatched before a PID or provider witness exists. Job registration alone is insufficient.
4. Keep admitted review target/build-dir isolation. Auth comes from the existing gateway refusal and current quota from the leg store. The new terminal reasons come from typed wait or launch state. Preserve pre-existing provider state for either local result.

- E1. `host_ready._cargo_lease_for`, `cargo_lease`, host readiness cleanup and trim, and `tools/preflight.py` cache reuse, build policy and Cargo invoke.
- E2. `SpawnerRunner.spawn`, reached from base and routed CLI/MCP through service and the seat launcher, and `overflow.native_spawn`, including forwarded launches on the native target host. Keep dry-run, cancellation, monitor/finish lifetime and isolated review paths.

The delivered fixture uses its own target, reaches the mocked native launch and proves existing record provenance. Use the Rust source as the holder witness and keep compiler artifacts isolated from the synthetic contention target.

## Acquisition and ownership

- Use the existing sibling OS lock for the actual protected target. Resolve equivalent ancestor aliases to the same lock file. Follow existing Rust target admission for unsafe leaf aliases. Python must use the same resolved target as the cooperating Rust writer, or refuse ambiguous alias admission if compatibility cannot be established. Python exclusive reclaim locks the target being reclaimed. Preserve the existing protected root rules for private preflight targets and admitted review isolation. Allocate no second lock, unlink no lock file on release and grant no bypass from an inherited marker, metadata or PID.
- Ordinary production shared acquisition defaults to **5.0 seconds** measured from the acquisition request, including async executor queueing. Clip the effective deadline to the earlier absolute probe deadline. Use nonblocking attempts, a stop-aware retry interval capped at 100 ms, and a final sleep clipped to remaining time. Skip attempts after an expired absolute deadline. Check time and stop again after an acquisition and close a late successful handle. An explicit zero-wait request without an expired absolute deadline gets one attempt without sleep. Preserve exclusive cleanup wait and immediate exclusive semantics.
- Raise a typed `OSError` with code `cargo_lease_timeout` for exhausted shared acquisition. Carry `waited_ms`, `wait_budget_ms`, `contention_observed` and the selected lock identity when observable. Known contention requires an OS conflict on that exact file. Use device/inode from the attempted POSIX lock descriptor. On Windows capture the physical target selection and volume/file identity when available without weakening share flags or blocking. Keep raw path/identity in local evidence, sanitize shared excerpts, and report unavailable identity explicitly.
- `reuse_policy` performs an immediate shared attempt and treats contention as a cache miss. Keep the safe fallback. Bounded failures in `build_policy` and ordinary Cargo invoke name the local lease failure, launch no Cargo without the lease and preserve the independent checks. Train CLI staging retains the exclusive guard.
- The async worker result owns one handle until transfer to a caller. Close failed POSIX attempts and any handle won by an abandoned/cancelled request, including cancellation after executor completion and before delivery. A shared stop signal and one-way ownership transfer or an equivalent existing primitive are sufficient. The caller keeps a transferred handle through launch failure or verified child exit, using existing monitor/finish cleanup. Dry runs acquire nothing. A crash releases its OS handles. No process signal is issued for contention.

## Probe classification and settlement

- Reuse `probe_cleanup`'s task-local ownership. The probe sets an in-memory state with deadline, launch stage, lease evidence where known and an owned stop signal. Gate every process factory invocation after pre-launch setup, including admitted review targets. Recheck deadline after synchronous bookkeeping and put no yield between the final gate, dispatch transition and factory invocation. Keep `claim_first_dispatch` on its existing service boundary.
- A typed exhausted shared acquisition yields `cargo_lease_timeout`. Expiry of the outer `asyncio.wait_for(asyncio.shield(spawn_task), remaining)` before the creation transition yields `probe_pre_dispatch_timeout`. Record the local stage and measured contention if applicable. The latter classification also applies to expiry during other local preparation. Set the owned stop before any await in the timeout or cancellation handler. Late worker settlement or lock release cannot cross the gate. Any already-registered job gets a terminal local outcome. External cancellation propagates after owned cleanup and creates no provider-state writes.
- `before_launch`'s single-flight waiter timeout remains a distinct joiner budget. The joining caller returns its ordinary budget reason while the owner's probe continues. When a probe has returned either typed local fault, including during snapshot-error recovery, carry it into the routed terminal attempt with no provider fallback. Keep existing definite auth and quota ordering. Direct probe JSON exposes `ok=false`, `infra=true`, `state=host-not-ready` and bounded `local_fault` data with stable code, stage and safe timings. Base/routed regular spawn and native spawn retain the typed lease failure through their existing run/job/attempt record flow before output classification. Non-lease native launch failures retain their existing outcome.
- After creation begins, expiry while creation is in flight or at completion is a dispatched timeout with the existing owned cleanup. Preserve successful probes, actual provider quota, limited-leg admission, ordinary infrastructure exceptions and auth behavior. New local outcomes produce zero pass/fail/down/limit writes and skip child provider output and serving inference. Retain disposable context until it is safe to clean up.
