# Review seat policy and checkout

`apply_review_permissions` disables session sharing for every OpenCode review seat and returns a reason when the final config is not the read-only policy and the launch is then refused with `render_refused`: a config that is not JSON, has no `permission` object or no default deny (`*`), grants anything outside the policy (an extra allow, a bash command outside the checkout list), adds a tool source (`mcp` not `{}`, `plugin` not `[]`) or does not disable sharing. Environment layers (managed config dir, OPENCODE_* names, per-job dirs) only mark the run unwitnessed through `_opencode_tools_denied`. After an OpenCode review run the stream's permission-refused tool calls are recorded as a `permission_denied` event with a count. A worker review whose disposable checkout is no longer the pristine pinned head after a completed run (moved HEAD, attached branch, modified or untracked file) fails with reason `review_checkout_dirty`; the checkout is removed either way.
