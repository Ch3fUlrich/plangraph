# Review seat policy and checkout

`apply_review_permissions` disables session sharing for every OpenCode review seat and returns a reason when the final config is not the read-only policy and the launch is then refused with `render_refused`: a config that is not JSON, has no `permission` object or no default deny (`*`), grants anything outside the policy (an extra allow, a bash command outside the checkout list), adds a tool source (`mcp` not `{}`, `plugin` not `[]`) or does not disable sharing. Sharing must be explicitly `disabled`. Before the process exists `review_layers_refusal` also refuses a launch whose environment lets a configuration layer add tools or override the policy: an active managed `opencode.json(c)`, an OPENCODE_* name outside the allow list, project or Claude Code layers not disabled, HOME or the config dirs outside the per-job dir, or `OPENCODE_CONFIG` not an empty config inside it. After an OpenCode review run the stream's permission-refused tool calls are recorded as a `permission_denied` event with a count. A worker review whose disposable checkout is no longer the pristine pinned head after a completed run (moved HEAD, attached branch, modified or untracked file) fails with reason `review_checkout_dirty`; the checkout is removed either way.

Deferred: the review launch still uses a disposable clone; leasing the Rust seat pool at launch and finishing it at completion is `plangraph:REVIEW-LAUNCH-USES-RUST-SEAT-POOL`.
