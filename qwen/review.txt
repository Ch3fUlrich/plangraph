## V1 — Ack storage

The ack is exclusively the `ok=1` audit row written by `Store._run` on successful completion of `_ack`'s inner `fn`. A refused ack (role check, validation, not_found, bad_state) causes `fn` to raise `Refused`, so `_run` writes `ok=0`. The listing SQL in `_ALARMS` filters `a.ok = 1`, so a refused row can never hide an alarm. `test_a_refused_ack_is_audited_but_keeps_the_alarm_listed` confirms this explicitly.

No forging path exists: the only call site for `store._run(principal, "ack_alarm", …)` is `_ack` in `routes.py:_ack`. No other verb string reaches audit with `action='ack_alarm'`. SQL injection is not applicable because all parameters are bound (`?` placeholders) and the `||`/`CAST` concatenation is on the integer PK only.

No issue.

## V2 — Authz on write

`routes.py:_ack` checks `principal.role not in ("router","system")` first inside `fn`. The key is computed before `_run` (mirroring `_resignal`), so a non-privileged principal with a valid int still gets an `ok=0` audit entry with key `alarm:<id>`—never `ok=1`. Boolean `True`/`False` are excluded by `not isinstance(aid, bool)` in the key expression and re-checked inside `fn`. Strings, floats, None, and lists yield `key=None` and hit `validation` inside `fn` (after the role check, which is correct ordering). Negative ints produce key `alarm:-1`, the query returns no row → `not_found`, `ok=0`. No bypass surface in the diff.

No issue.

## V3 — Authz on read (scoping)

`_alarms` builds `allowed = None` for `_SEES_ALL` roles, else `set(principal.projects or [])`. Filtering applies in the list comprehension: `if allowed is None or _project(r["key"]) in allowed`.

- **Empty projects**: `set([] or [])` → `set()` → nothing matches → zero leaks.
- **Keyless alarm (empty key)**: `_project("")` → `""` → never in a named-projects set → invisible to non-SEES_ALL. Contract satisfied.
- **Key without colon** (`"demo"`): `_project("demo")` → `"demo"` → matched against project list; correct.
- **Odd key** (`"a:b:c"`): split on first `:` → `"a"`; consistent with questions path.
- **Scoping after error path**: The `except _UNREADABLE` block returns `{"alarms": [], "error": …}` before the list comprehension runs—no rows exist, so no scoping gap.
