## V1 Unit correctness

- Service (`plangraph-projector-reconcile.service`): `Type=oneshot` correct for a timer-activated batch job; no `[Install]` section on the service (correct — only the timer is enabled, and the test enforces this). `TimeoutStartSec=15min` is valid and honored for oneshot. Specifier `%h` expands in user-unit `WorkingDirectory`, `Environment=`, `EnvironmentFile=`, and `ExecStart` — all uses here are legal. `EnvironmentFile=-%h/...` with the `-` (optional) prefix is valid systemd syntax.
- Timer: `OnCalendar=*-*-* 03:30:00`, `RandomizedDelaySec=10min`, `Persistent=true`, `Unit=plangraph-projector-reconcile.service`, `[Install] WantedBy=timers.target` — all valid user-timer directives; `Persistent=true` combined with the README's "cannot wake a suspended host" caveat is accurate.
- Minor / misleading (non-blocking):
  - `After=network-online.target` — the user manager has no `network-online.target`; `After=` on a nonexistent unit is a harmless no-op, but it conveys nothing (it won't delay the run for connectivity). Consider `After=plangraph-keeper.service` only, or drop it.
  - `After=plangraph-keeper.service` orders only when both units start in the same transaction; a timer-fired oneshot does not pull keeper in, so this gives no guarantee keeper is up when reconcile runs. Harmless if reconcile reads keeper state directly (SQLite/keeper.json), but the directive is decorative. Worth one comment line at most.
  - `WorkingDirectory=%h/code/plangraph/.claude/worktrees/proposal` bakes a worktree name into a deploy unit; acceptable here only because the stated context says the existing keeper unit uses the identical paths — consistency preserved, but it is a path a real deploy must edit (README §4 does say that).
