**V3 – can any shape make a red or still‑running CI report ok (false‑green)?**  
- The implementation first collects *failures* before *pending*, and only returns `None` (green) when **no failures**, **no pending**, and **not all skipped**.  
- Edge‑case shapes that could slip through:  
  * A run missing the `"status"` field altogether but with a non‑`None` `conclusion` that is *not* `"success"`, `"skipped"` or `"neutral"` – it would be treated as a failure (because `norm` is checked).  
  * A run with an integer `id` that overflows Python’s `int` range – still comparable, no impact.  
- No combination of fields can produce a failing or pending CI that is mistakenly reported as green; the ordering of checks (`failures` → `pending` → `all‑skipped`) guarantees that any red or running state is reported.
