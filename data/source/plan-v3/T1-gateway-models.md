## Combo contract v3 (requirements; the lane picks the OmniRoute mechanism and proves it)
| # | Requirement | Why |
|---|---|---|
| C1 | Every combo sets an explicit `context_length` = smallest window among its legs; a leg below the tier floor is excluded (floors: orchestrator 200k, worker 128k, reviewer 64k) | live advertised min(windows) caused 115 overflow rejections + 112 compactions |
| C2 | ≥ 3 legs from ≥ 2 model families per chat combo; reviewer pools ≥ 3 families so two cross-family seats exist even with one family rate-limited | single-model combos and same-model tails broke the 2-family review rule |
| C3 | Leg order by tier group: trial → free → credits; no paid legs in OmniRoute (paid = Sonnet via Claude only) | operator tier order; deepseek/meta cost |
| C4 | Equivalent free legs rotate (round-robin/LRU) with 15-min session stickiness; Protect (adaptive rate-limit protection) on for API-key providers | parallel orchestrators hit single-provider limits; cache stays warm within a session |
| C5 | Gemini AI Studio free (20 req/day) is never a head leg | 16/394 success; wastes one attempt per call |
| C6 | Effort per combo declared in the registry (max rung allowed where the model has it); `low` is never rewritten; ack budget ≥ 2048 tokens for reasoning models lives in the registry | effort capped at high; low→high gateway bug |
| C7 | Single source: registry → `combos.json` → OmniRoute apply, LiteLLM config, opencode/IDE configs and `docs/models-proposed.md`, all generated with `--check` drift tests in CI | 9 repo combos never applied; stale docs/configs |
| C8 | Multimodal combos separate: `stt-*`, `tts-*`, `image-*` (+ `3d-*` if served); never mixed into chat tiers; callable by subagents | operator item: images/STT/TTS/3D |
| C10 | Session shape by role: **orchestrator combos** use long stickiness (one model per session for hours while healthy — warm prompt cache, consistent behaviour; switch only on failure); **worker/reviewer/researcher combos** are per-task throwaway sessions on rotating free pools (round-robin/LRU across providers and families, no long stickiness), so free tiers absorb the volume and rate limits spread | operator 2026-10-01: long sticky orchestrators, disposable per-task workers |
| C10a | Exact OmniRoute settings for C10 (code-verified 2026-10-01, research/2026-10-01-omniroute-caching.md): **global** `promptCacheAffinityEnabled: false` (otherwise rotation collapses onto one target for a shared system prompt), `sessionAffinityTtlMs: 86400000`; **orchestrator combos** `strategy: priority`, `context_cache_protection: true` (model pin; clears after 3 failures), `context_length` = primary model window, clients send a stable `X-Session-Id` (not `x-omniroute-session-id` — that one is observability only); **worker pools** `strategy: round-robin`, `config.stickyRoundRobinLimit: 1`, `context_cache_protection: false`, `context_length` = smallest window in the pool + `contextRequirements {minContextWindow, contextFilterMode: strict}`, tasks bounded below it (global compression stays off — it busts prefixes on 3.8.50); `UNIVERSAL_CONTEXT_HANDOFF_ENABLED=false` after the upgrade to ≥ 3.8.51 (its switch summary costs an extra call). The response cache only serves `temperature: 0` requests — irrelevant for agents | sticky + rotation proven live in T1-COMBO3 |
| C11 | Chat-facing combos for people (Open WebUI) are separate from agent combos: `chat-*` curated tiers + OmniRoute `auto/*` where measured better, plus selected single models | operator: Perplexity replacement (T6-OWUI) |
| C9 | Async/long providers (Grok Bot) get their own combo, no fallback, no retries, timeouts ≥ 700 s | a timeout must not resend a task to another model |
