## V1: Schema, Upgrade, and Postgres Parity

**PASS.**

- Column parity: SQLite `METRICS_DDL` defines `(day TEXT, metric TEXT, value REAL, source TEXT DEFAULT '', computed_at TEXT, PRIMARY KEY (day, metric))`. PG `_V4` maps identically: `REAL` → `DOUBLE PRECISION`, `TEXT` → `TEXT COLLATE "C"`, same PK. `schema.py:210-222` vs `schema_pg.py:398-410`.
- Idempotent v10 upgrade: `db.py:_upgrade` calls `conn.executescript(METRICS_DDL)` (line 142 of post-diff). The DDL uses `CREATE TABLE IF NOT EXISTS`, so re-running is safe. SCHEMA_VERSION 10→11 triggers the upgrade path once.
- Authorizer: A plain `CREATE TABLE IF NOT EXISTS` with a single PK is identical in shape to every other DDL already in the upgrade chain (`DESIGN3_DDL`, `OUTBOX_DDL`, etc.). No triggers, indexes, or cross-schema references.
- copy_to_pg order: `"metrics"` is inserted between `"budget"` and `"projector_applied"` (line 25). Metrics has no FK into any table; projector tables also have no FKs back. Ordering is dependency-free.

## V2: set_metrics / get_metrics Store Logic

**PASS.**

- Role gating: `_set_metrics` calls `self._require_role(principal, "router", "system")` before any validation. `_get_metrics` does not gate beyond authentication (docs: "any authenticated role").
- Validation: day checked with `_day()` (strict ISO format round-trip). Metric name checked with `_NAME_RE.fullmatch`. Value rejects `bool` (line `isinstance(value, bool)` guard before int/float check), rejects non-finite via `math.isfinite`. Source allows `None`→`""`, rejects non-string or >64 chars.
- Atomicity of mixed batch: All items are validated and collected into `prepared` list before the write transaction opens (`with self._write():` only runs after the for-loop that can raise). A failure on item 3 of 5 leaves no partial write.
- SQL injection / portability: All parameters go through `?` placeholders. `ON CONFLICT(day,metric) DO UPDATE SET value=excluded.value, ...` is valid in both SQLite ≥3.24 and PG. The `LIMIT` clause uses `str(_METRICS_MAX_ROWS)` which is a module-level int constant, not user input.
- Row cap: `_METRICS_MAX_ITEMS = 50` on writes; `_METRICS_MAX_ROWS = 1000` on reads. Enforced before SQL execution.
