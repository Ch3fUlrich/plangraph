V3: SnapshotWriter._failed / _succeeded / _write_locked / flush

Counters race: `self.failures` and `self.alarm` are mutated in `_failed`/`_succeeded`, which are called OUTSIDE `self._cond` inside `_write_locked`. In the normal operating path, only the writer thread calls `_write_locked`, so mutations are single-threaded. `flush()` now calls `self._succeeded()` inside its `with self._cond:` block, so a shutdown-flush and a running `run()` tick could theoretically race on the counters. In practice flush is invoked after the thread has stopped (or as the last action); CPython GIL makes int reads/writes atomic. Not a bug in the merged model but worth noting: no lock protects the counters, relying on the thread model.

Alarm once per streak: `if self.failures == ALARM_AFTER` (equality, not `>=`) guarantees exactly one ALARM line per failure streak of length >= 3. `_succeeded` resets both `failures` and `alarm`, clearing the field for the next streak. Correct.

No secret in log lines: `_failed` logs `type(exc).__name__` only. The docstring explicitly states "exception type only: messages can carry paths". The ALARM message is a fixed string. No user data, paths, keys, or serialized secrets leak.

No behaviour change to retry/backoff: `_write_locked` still returns `False` on exception, `True` on success — the existing wait/backoff loop in `run()` is untouched. The only additions are logging and counter updates that do not influence control flow.

Minor note on `flush()`: `_succeeded()` is added to the success path but no corresponding `_failed()` in the except path. A flush failure will not increment `self.failures` or trigger ALARM. This is arguably intentional (daemon is shutting down, no retry) but creates an asymmetry where a preceding streak of in-run failures could be cleared by a successful flush without a recovery log line (since `_succeeded` only logs if `self.failures > 0`, and the failures count was incremented by the run thread — so it would actually log recovery). This is cosmetic, not a correctness issue.
