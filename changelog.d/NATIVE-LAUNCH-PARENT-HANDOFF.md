The fleet session run record keeps the launching session as `parent_session` (the `--parent` name of `fleet-launch`), so completion events can reach the parent by name. Skipped here: the launch.status receipt consumer, the retry of disk or cache refusals beyond the admission window and the terminal and explicit-resume handoff belong to the plan-order launcher, which is not in this repository; they are the slice `NATIVE-LAUNCH-PARENT-HANDOFF slice` of the batch.
