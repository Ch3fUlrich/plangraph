Native writer launches now refuse an item key a live writer run on the host that runs them holds, naming the run: `overflow.native_spawn` calls the new `pg-spawnd lane-admit` verb against its own state, so MCP, CLI, a queued launch and a forwarded target are all checked (a target's refusal keeps its reason and holder, and the MCP reply carries `data.reason`) and a holder on another host never blocks a launch placed elsewhere. A run record whose liveness cannot be decided refuses every keyed launch (reason `lane_unreadable`); the check does not serialize concurrent dispatches. Deploy: install the new binary, then restart the spawner MCP service; no data migration.
