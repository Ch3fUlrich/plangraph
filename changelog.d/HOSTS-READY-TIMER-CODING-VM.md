- **HOSTS-READY-TIMER-CODING-VM:** Add `deploy/systemd/pg-host-ready.{service,timer}`: every two minutes `python3 -m plangraph.spawner.host_ready` probes each placement host of the registry that has a spawner source and writes `host-ready/<host>.json`, so overflow placement stops reading every remote host as stale. The timer interval plus the probe timeout is tested against `host_ready.MAX_AGE`, a registry fixture publishes two fresh records and none for a host without a spawner source, and the install and check steps are in `docs/host-tools.md`. The module probes import from the resolved source directory (`PYTHONSAFEPATH` safe) on the SSH and WSL paths, the unit treats only the distinct `--not-ready-exit 3` status as success so crashes and unpublished records still fail it, `host_ready --check-records` reports ready, not-ready, stale and missing records, and `deploy/bootstrap.sh --host-ready-timer` installs, enables, runs and verifies the units. Registry hosts without `roles` are probed as registry hosts (source directory, tools, trust, and the session unit of `env.PG_SESSION_UNIT` when configured), and `--host-ready-timer` is a standalone bootstrap mode.
