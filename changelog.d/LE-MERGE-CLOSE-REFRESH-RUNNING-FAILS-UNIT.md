- **LE-MERGE-CLOSE-REFRESH-RUNNING-FAILS-UNIT:** `plangraph merge-close` now ends an applying pass as a skip (one line `merge-close: skip, merge index refresh still running (next run retries)`, exit 0, no close attempted on the expired index, rows and `continue` line of earlier pages kept) when another run's merge-index refresh is still running at the end of the bounded wait, so `pg-merge-close.service` no longer shows failed for it. `--count`, `--deploy-status` and `reconcile-merged` still report that state as an error, and transport or invalid-response errors keep exit 1. The refresh status poll returns a typed pending outcome, and each refresh request ends by the earlier of the refresh and pass deadlines. Only a request that ran into its own time limit (curl exit 28, now `keeper request timed out`) counts as expiry, so a late refusal stays an error; refresh requests get the exact fractional time left and a refresh answer that arrives after its wait is discarded.
