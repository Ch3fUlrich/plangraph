Host disk alerts are keyed by filesystem: each crossing above 85% used queues one measured alert naming the five largest directories of that filesystem, optionally after a bare one, and recovers only on a sample of the same filesystem at or below 85%. Collectors may supply keyed `disks` samples with consumers; the local host reads `disk-watermarks.json` rows by device, and only rows measured after the last observed recovery. Deploy: the timers run installed binaries, so build both with `cargo build --manifest-path rust/Cargo.toml -p pg-worker-core --release --bin flow-watchdog --bin pg-disk-hygiene` and copy `flow-watchdog` and `pg-disk-hygiene` from `rust/target/release` to `~/.local/bin` on each host; both units are oneshot, so the next timer run uses them and no unit restart is needed. Legacy collectors that send `work_used_percent` must send it on every row (`[]` when empty).
