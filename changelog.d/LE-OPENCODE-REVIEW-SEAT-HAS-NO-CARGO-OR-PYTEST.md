An OpenCode review seat now gets cargo (`~/.cargo/bin` of the launching user, read before the seat swaps HOME) and a trusted Python on its PATH, the same interpreter lookup the Sonnet seat uses: the first of `PREFLIGHT_PYTHON`, the service venv and the service checkout's `.venv` that really runs `python -m pytest --version`. The seat's `python` and `python3` are wrappers that exec exactly that interpreter. The review checkout is the code under review and is never run or trusted for this, and the harness itself and host admission are looked up on the PATH the launch had. The review skill treats a test command that cannot start as a HIGH finding instead of accepting on reading (plangraph:LE-OPENCODE-REVIEW-SEAT-HAS-NO-CARGO-OR-PYTEST).
