`plangraph ci-watch` files CI-FIX items only for main and open non-draft pull requests that are not `CI probe:`
or landing-train (`land/*`) pull requests. After each scan a sweep cancels the open CI-FIX items of a pull
request that closed, became a draft, probe or train, or moved to a new head (the failing run's head is now
recorded as `sha` in the task state), with the reason in the keeper. The first run with `--keeper` cancels
the backlog; the sweep line is `cancel: <key> (<reason>)`. The sweep runs before the scan, reads the head of older rows from the stored run, and without `--keeper` keeps the row. A failing landing train still reaches the writer recorded for it (never a fix item), a pending cancel is kept for rows without a stored head, and every key an item can live under is cancelled before its row goes. A train and an ordinary pull request on one commit each keep their path, a legacy row's head is recorded when GitHub resolves it, and the keeper key is saved before the create. A run goes only to the pull request it names (its `pull_requests`, else its only pull request, else its branch) and a push to main is main's alone; the chosen keeper key is on disk before the create is sent. A run that names no pull request is matched by head branch and head repository and stays unassigned when that is ambiguous; every change to `tasks.jsonl` goes through one locked read-modify-write. A run that names no pull request is assigned only when its branch matches and both it and the pull request name the same head repository.
