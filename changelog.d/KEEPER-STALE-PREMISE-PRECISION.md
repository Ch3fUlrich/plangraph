The stale-premise gate reads decision ids from the item's premise fields only (title, description, done criteria, note, source), recorded on the definition events that cite one, so metadata can no longer move a decision watermark: `session`, `similar`, `category` and `supersedes` are validated create and import fields (`session` one line, credential-free) carried on the creation event (checked for credentials together with the note and each other, written back by the YAML export, and carried through a rehome) and no longer folded into the note. The fallback watermark of an uncited item is anchored at its creation or last real premise change (re-saving the same text moves nothing), the item's own source decision is never "newer", and the router's `reconfirm KEY D-NNN` records a premise re-read as its own audited event (no edit) that raises a per-item floor that every later real change of the premise text voids for good (a revert does not revive it, re-saving the same text keeps it); ordinary claims, system and phase-worker leases (which now enforce the newer-decision and retired-premise checks on a fresh, strict decision read) and ready read the same floor.
