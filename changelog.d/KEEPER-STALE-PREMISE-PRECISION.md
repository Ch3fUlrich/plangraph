The stale-premise gate reads decision ids from the item's premise fields only (title, description, done criteria, note, source), recorded on the definition events that cite one, so metadata can no longer move a decision watermark: `session`, `similar`, `category` and `supersedes` are validated create and import fields (`session` one line, credential-free) carried on the creation event and no longer folded into the note. The fallback watermark of an uncited item is anchored at its creation or last real premise change (re-saving the same text moves nothing), the item's own source decision is never "newer", and the router's `reconfirm KEY D-NNN` records a premise re-read as its own audited event (no edit) that raises a per-item floor bound to the premise text read, so a later edit of that text voids it; ordinary claims, system and phase-worker leases (which now enforce the newer-decision and retired-premise checks on a fresh, strict decision read) and ready read the same floor.
