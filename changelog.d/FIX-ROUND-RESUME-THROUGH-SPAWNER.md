A fix round for a placed native writer resumes the same Codex session on its owning host through the spawner: `pg-spawnd resume RUN_ID --prompt-file PATH [--host NAME]` and `python3 -m plangraph.spawner.cli resume RUN_ID` route the prompt to `pg-spawnd resume-local`, which starts the resume detached. The resumed turn's sandbox lists the linked worktree's git directory (`.git/worktrees/<name>`) as writable, so its fix commit lands. The owning host acknowledges a round only after the resume has reopened the run (one prompt file and log per round), and the origin receipt stays running (`resume_requested`) until the target reports that round, so `result` and `wait` never return the earlier head. The route waits 45 s for the owner's 30 s reopen wait and reconciles a lost acknowledgement from the target's `resume_number`; a failed prompt write releases its round. Each routed round carries a request id that the target records on the run (`resume_request_id`) and echoes; success, and the reconciliation of a lost acknowledgement, require that exact id. The local owner path waits as long as the ssh path. `resume-local` acknowledges a round only when the run record names this request's id and reports the round it observed; the local and ssh paths apply the same receipt check.
