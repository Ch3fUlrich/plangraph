An item that blocks a higher-priority item is ordered at that priority: `ready`, the feeder and the web table sort by an effective priority computed once per request from the dependency graph (the stored value never changes; shown as `8 -> 10 via KEY`); the snapshot carries `effective_priority` and `priority_via`; `reap` records the daily count of raised items and the longest chain. Deploy: restart the keeper (it computes the value) and republish the snapshot; the feeder and the web page read the new fields, so no other deploy step is needed.
