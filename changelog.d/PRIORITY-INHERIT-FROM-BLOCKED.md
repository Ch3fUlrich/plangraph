An item that blocks a higher-priority item is ordered at that priority: `ready`, the feeder and the web table sort by an effective priority computed once per request from the dependency graph (the stored value never changes; shown as `8 -> 10 via KEY`); the snapshot carries `effective_priority` and `priority_via`; `reap` records the daily count of raised items and the longest chain. Deploy: restart the keeper (it computes the value) and republish the snapshot; rebuild and install the `plangraph` CLI on every feeder host (`~/.local/bin/plangraph`, run by the `pg-feeder` timer), because the installed binary still orders by the stored priority until then; the web page reads the new fields from the snapshot and needs no other step.
