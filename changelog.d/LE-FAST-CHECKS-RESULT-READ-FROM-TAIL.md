`affected_tests.py --run` ends with one line `AFFECTED rc=<n> batches=<k> failed=<m>` and exits non-zero when any batch failed, so a failing early batch can no longer hide behind a passing last one. `plangraph fast-checks --owned-worktree` now writes a receipt for every outcome (`head`, `result green|red`, one `check <label> rc= wall=` line each) and the same receipt as a git note (`refs/notes/plangraph-fast-checks`) that travels with the pushed head. `plangraph fast-checks --stamp-green HEAD` answers the push gate. The review launch, the step runner's push and the lane push refuse a head whose receipt is missing or red. A receipt is green only with its own `head` line, one `result green` and at least one well-formed `check ... rc=0 wall=` line; an empty or truncated file is not. An empty selection also ends with `AFFECTED rc=0 batches=0 failed=0`. The shared batch brief renderer names the one `plangraph fast-checks --owned-worktree` command (not a producer's list) and, with `run.push`, the per-item `PUSH:` line.
