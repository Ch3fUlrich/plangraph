pg-worktree-sweep and the reaper now report `live-run` only for a tree owned by an unfinished (or survivor-holding) run record whose checkout or attempt is at or inside the tree, and `pinned` for operator pins and reserved names; both still protect, and a run recorded only in an ancestor directory no longer counts as owning the trees below it (the reaper still refuses to move such a tree). `pg-reap` facts without `pinned` still parse as false.

Ownership evidence is the set of distinct `(record.json run_id, canonical worktree path)` pairs of unfinished runs, using the same `finished` and `paths` rules as the code, not a count of pins. On the development host that host's run state held 2979 readable records, 1 unfinished run (`running`), giving 1 pair and 1 distinct worktree. The workstation figure (the earlier claim that its 153 of 245 `live-run` rows were pins is withdrawn) is not measured here and still needs the same join on the workstation's run state before the result is reported.
