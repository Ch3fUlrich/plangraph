CI builds `pg-spawnd` once per run (`build-spawnd`, shared as an artifact), restores Cargo caches with `restore-keys` and saves them only on pushes to the default branch, balances every pytest shard from one pinned duration map per suite (`.github/pytest-durations-*.json`), and uploads per-shard timings that `ci-gate` combines for the next train. A red pytest or `cargo test` step is classified by a same-SHA retry (`ci-flake classify`) and stays red; active quarantine entries (ledger of the base) run in a reporting step with owner and expiry in the summaries. See `docs/ci-gate.md`.
The `pg-spawnd` artifact carries a digest and source-commit manifest that the fetch action verifies before staging it for the fleet fixture (`PLANGRAPH_TEST_FLEET_SPAWND`); every pytest shard runs the real fleet fixture on it.
