`pg-spawnd session` respawns a numbered worker session (a role in the host policy's `worker_roles`) with `--resume <saved session_id>` and the saved `-n`/`--remote-control` name, so a fix round reaches the writer that holds the batch context; and a launcher counts the host it runs on as local by kernel hostname as well as by policy name. A numbered worker respawn whose saved `session_id` is absent or not a plain token is refused with the reason instead of starting a fresh session. A forwarded launch runs the target's launcher with the forwarded prompt (also for a dry run, without leaving files) and reads the target's own saved session record. The forwarded-launch receiver starts the destination's `pg-spawnd session` (every forwarded launch is refused where it is not installed; the legacy entry point is no longer used) and looks up saved sessions under the target's `ROUTING_STATE_DIR`.
