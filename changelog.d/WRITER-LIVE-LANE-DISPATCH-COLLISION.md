Native writer dispatch refuses an item key that another live writer run, an unmerged remote lane branch or an active reservation of a concurrent launch already holds, naming the lane. Every key of the card (`item_key`, `item`, each `item_keys` member) and of the brief is checked with the one key grammar of run records (the id part may hold colons, so `demo:ITEM:detail` never reads as `demo:ITEM`; record and card keys are read by that grammar alone, a colon ends a key only in a `## key: title` heading with title text, never in `### key: | title`, `Item key:` or `Plan item:` lines), and the check and the reservation are one step under the lock of the dispatch state directory, so two concurrent launches on a host cannot both pass. Launch options (dry run, absolute repo, wait) are validated before anything is reserved. Each launch owns its own claim per key, so an override launch never replaces the first launch's claim; a claim is released when its launch ends, so a failed launch never blocks the retry; a claim nobody released holds for 2 minutes before the supervisor is started (a crash backstop) and for 10 minutes once it is started, because that supervisor can still register the run after the dispatcher died; a launch removes its claim under the same lock as every admission, so a dispatch never reads the runs before a registration and the claims after its release. Only published claim files count, and a failed publication leaves no temporary file. A branch holds a key only when its slug appears as whole tokens of the branch name without the remote name (`fix` does not match `fixture`, `demo:ORIGIN` does not match every `origin/` branch). A deliberate second lane passes only with a nonblank `card.lane_override_reason`; a `lane_override` in the typed prompt or a caller-supplied `card.lane_override` never admits one, and the run record keeps the card's reason as `lane_override` next to the admitted `item_keys`. The admitted keys are added to the card after its size check, so a card within the existing limit is never refused for them. Deploy: restart the spawner MCP service and the Python spawner service after the binary and `notify.py` update; no data migration.
