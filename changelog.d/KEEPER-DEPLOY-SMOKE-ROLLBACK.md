- Keeper deploy tool `tools/keeper_deploy.py`: live smoke with a default 60 s API budget after restart and running-process verification (health, probe claim+release, close_merged route); a failed smoke restores the previous drop-in set, restarts and exits non-zero.
- Smoke accepts the expected router-only refusal after claimant checks, or an explicit authenticated close_merged dry-run result, bounds smoke API calls and release cleanup under one deadline (each systemctl invocation has its own 60 s timeout), and restores on unexpected exceptions. CLI --dry-run only prints the drop-in.

- Keeper deployment accepts the expected router-role refusal after claimant smoke, replaces stale managed drop-ins deterministically, and verifies the effective working tree and Python path before smoke; mismatches restore the prior deployment.
- Apply checks the normalized checkout HEAD against the requested SHA before any backup/write, and verifies MainPID plus running cwd, PYTHONPATH and daemon command rather than trusting unit properties alone.
- After a complete restore, reload and restart report independent outcomes; a failed or partial restore skips both and reports its backup path. Recovery ignores SIGTERM/SIGINT before its first condition. Nested smoke timers preserve the earlier deadline, and relative/trailing-slash trees are normalized before use.
