Harness binaries are found by one resolver (`resolve_harness_binary` in `routing_support/clients.py`): an env override, the `harness_bins` table of the host in the hosts registry, then the search path with the user install dirs a systemd-run unit lacks, with a logged warning. Model discovery, spawn, leg probe and host admission all call it. A missing binary is refused as `harness_not_found <name> <searched paths>`, leg state shows `harness_missing`, a seat that ends without a verdict keeps that reason, `plangraph review` prints the refused run's reason on its SEAT and REVIEW lines, and two runs without a verdict for the same cause inside 30 minutes raise one alert in `alerts.jsonl` of the review state directory.
