A keeper claim now refreshes only the item's own repository from origin and reuses an index that finished refreshing within `claim_index_window_s` (default 5 s), so a batch or claims in quick succession cost one origin refresh per repository instead of one per repository per claim. `GET /v1/health` reports `claim_preflight_s`, and the CLI bounds `claim` and `claim-batch` by that budget plus 15 s instead of a fixed 15 s, so a claim that lands is not reported as "outcome unknown".
