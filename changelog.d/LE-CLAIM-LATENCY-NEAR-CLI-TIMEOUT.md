A keeper claim now refreshes only the item's own repository from origin (other repositories serve their last built index), and the keys of one `claim-batch` share that refresh, so a batch costs one origin refresh per repository instead of one per repository per key. `GET /v1/health` reports `claim_preflight_s`, and the CLI bounds `claim` and `claim-batch` by that budget plus 15 s instead of a fixed 15 s, so a claim that lands is not reported as "outcome unknown".
