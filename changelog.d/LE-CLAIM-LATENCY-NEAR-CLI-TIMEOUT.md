A keeper claim now refreshes the item's own repository from origin, and in parallel only those other repositories whose last built index is older than ten seconds or was never built (a recent one is served as built); the keys of one `claim-batch` and claims running at the same time share the refreshes, so a batch costs one origin refresh per repository instead of one per repository per key. `GET /v1/health` reports `claim_preflight_s`, and the CLI bounds `claim` and `claim-batch` by that budget plus 15 s instead of a fixed 15 s, so a claim that lands is not reported as "outcome unknown".
