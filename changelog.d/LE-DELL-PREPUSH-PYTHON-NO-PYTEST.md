The pr887 workflow-step test now runs the workflow command with the preflight interpreter first on PATH as `python`, so a host whose bare `python` has no pytest passes the pre-push hook. Registry host readiness probes the pre-push interpreter (checkout `.venv`, else `python3`) for `pytest` and `xdist`, records `python_ok` and fails the host with `python: missing ...`, so a push host is chosen only where the hook can pass. Registry host readiness runs `host_ready --test-tools` on the host, which picks the interpreter as the hook does (checkout venv, else `PREFLIGHT_PYTHON` with `~` and `~user` expanded, relative to the checkout, else `python3`) and reports a process umask or session-unit `UMask` that leaves new files group- or other-writable.
