The pr887 workflow-step test now runs the workflow command with the preflight interpreter first on PATH as `python`, so a host whose bare `python` has no pytest passes the pre-push hook. Registry host readiness probes the pre-push interpreter (checkout `.venv`, else `python3`) for `pytest` and `xdist`, records `python_ok` and fails the host with `python: missing ...`, so a push host is chosen only where the hook can pass. The probe resolves `PREFLIGHT_PYTHON` as the hook does (home- and checkout-relative) and reports a probe-shell or user-unit umask that leaves new files group- or other-writable.
